## 目标与范围

用户确认将 events 合入 common，集中表结构、三轮输出校验及三种 Store，并拆分配置加载、业务输入和 HTTP 请求构造。项目仍独立运行，不套顶层包，不增加安装、依赖或插件机制。

本次只调整代码归属、调用和导入，同步配置定位、测试及文档。三轮执行方式、数据字段、状态、配置摘要、校验内容、读取范围、请求预算、存储重试、保存确认、停止和恢复规则保持不变。现有待接入接口也保持原状。

## 目标目录及职责

```text
common/
├─ config.py                 AI、事件及任务配置加载，配置对象和摘要
├─ request.py                提示词模板替换及 HTTP payload 构造
├─ inputs.py                 原帖正文、当前记录及第二三轮业务输入
├─ table_schema.py           两张表字段、共用索引及各自表结构校验
├─ output_validation.py      严格 JSON 解析及三轮独立输出校验
├─ store.py                  TableStore、TaskStore、ResultStore 及阶段汇总
├─ history.py                事件历史及组内时间线
├─ time_rules.py             事件时间解析和范围选择
├─ network.py                网络线程、请求预算、限速和关闭
├─ response.py               接口外层响应解析
├─ persistence.py            指定列写入、排序及整批存储重试
└─ execution.py              第一轮和第三轮共用分段执行
```

初始化、三轮业务和启动入口目录保留。configs 下的 YAML、可选 .env 位置、相对路径解析和启动命令不变。

## 文件迁移与必要拆分

| 原位置 | 新位置 |
| --- | --- |
| common/ai_config.py 的配置对象、加载和摘要；events/config.py | common/config.py |
| common/ai_config.py 的 TaskRenderError、_render、render_payload | common/request.py |
| 入口内重复的任务 YAML 读取、字典及必填字段检查 | common/config.py 的 load_job_config；各入口仍指定自己的必填字段 |
| common/validation.py；events/schema.py 的字段和表检查 | common/table_schema.py |
| common/json_output.py；第一轮、第二轮及第三轮输出校验 | common/output_validation.py |
| common/store.py；events/store.py；round1/tasks.py | common/store.py，保留三个类 |
| events/inputs.py；第二轮 JSON 输入组装；第三轮 _impact_text | common/inputs.py，保留当前记录和历史内容 |
| events/history.py、events/time_rules.py | common/history.py、common/time_rules.py |

三个 Store 使用统一字段定义，第一轮结果列明确使用 POST_RESULT_COLUMNS，避免与事件表 RESULT_COLUMNS 混淆。类和方法的业务职责不合并为轮次条件分支。

三轮输出校验仍分别为 validate_first_round、validate_relation、validate_impact；第二轮候选 ID 由调用方传入。第三轮继续只做现有五字段及文本校验，本次不新增评分枚举。

业务输入在调用线程准备。第二轮仍在检索后构造候选输入，第三轮仍在认领后逐条组织请求。网络线程只接收已准备的文本，不读取数据系统，不重新查询或推进历史。第一轮直接使用正文，不增加空包装函数。

配置模块不依赖请求模块；请求模块使用配置对象和同一模板变量语法。环境变量优先、AI 配置同目录 .env、配置摘要基于原始提示词和 payload 的规则不变。任务配置使用现有安全 YAML 解析；初始化与处理入口保留各自字段要求及校验顺序，不强制提前加载 AI 配置。
