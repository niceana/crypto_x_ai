# round1帖子事件提取表字段

round1帖子事件提取表每帖一行，保存登记时的帖子输入及最新一次完整处理的结果。处理规则见 [关键规则](../rules/KEY_RULES.md)，项目关系见 [项目总览](../../project_overview.md)。

## 索引与字段

表格使用两层索引，名称和顺序固定为 `date`、`id`，即 pandas 的 `MultiIndex`。普通列恰好为下列九列。程序初始化任务和提交更新时，所有提交的普通单元格均为字符串，没有结果时写空字符串。运行端读取只检查结构和索引，普通列单元格原样使用，规则见下文。

| 索引或字段 | 含义 | 初始化值 |
| --- | --- | --- |
| `date`，索引第 1 层 | 源帖子的原始时间，对应原帖 `created_at`；保持原类型、时区和精度。 | 源值。 |
| `id`，索引第 2 层 | 帖子的唯一、非空白字符串 ID，与 date 共同定位行。 | 源值。 |
| `config_hash` | 提示词模板及 AI 调用参数的 64 位小写十六进制标识。 | 空字符串。 |
| `text` | 登记时的帖子正文。 | 源值。 |
| `user_name` | 登记时的用户名，仅作记录和保存核对。 | 源值。 |
| `status` | 未处理、处理中、成功或本次最终失败。 | `"0"`。 |
| `ai_response_content` | 最终 AI 回答正文，保留原文。 | 空字符串。 |
| `reasoning_content` | 最终推理文本，保留原文。 | 空字符串。 |
| `usage_json` | 最终响应 `usage` 的标准 JSON。 | 空字符串。 |
| `response_created` | 最终响应 `created` 按 Unix 秒转成的北京时间文本，格式为 `YYYY-MM-DD HH:mm:ss`。 | 空字符串。 |
| `error_message` | 最终失败原因，最多 512 个字符；成功时为空。 | 空字符串。 |

`date` 不能缺失，复合索引、ID 和列名均须唯一，同一 ID 不能对应多个日期。日期不会被处理时间或 AI 生成时间替换。

处理任务时，每批按列更新的行必须按原 `(date, id)` 严格递增：先按日期升序，同一日期按字符串 ID 升序；索引值及整行结果共同排序。并发答复按原键对应帖子，完成顺序不决定提交顺序；本批出现重复键时停止写入。

初始化源表需要字符串 `text`、`user_name`，保留原两层索引；其他源列不写入round1帖子事件提取表，无需提供 id 普通列。仅有旧 `username` 的源表不满足要求，round1帖子事件提取表也不接受额外的用户名列。

## 状态含义

| 保存的值 | 含义 | 下次运行读取到该任务时 |
| --- | --- | --- |
| `"0"` | 等待处理。 | 保持 0。 |
| `"9"` | 已标记开始处理，正在请求、等待重试或等待保存结果。 | 重置为 0。 |
| `"1"` | 成功结果已保存。 | 保持 1，跳过。 |
| `"-1"` | 本次最终失败及其原因已保存。 | 重置为 0。 |

状态只是本地任务记录。`"9"` 不证明请求已发送，`"1"` 不证明回答的业务判断正确。

## 数据有效性

- 本程序生成的 `config_hash` 是 64 位小写十六进制；初始为空。新成功结果包含回答和摘要，错误为空。运行端不逐格检查历史字段格式或空值。
- 新结果的非空 `usage_json` 使用标准 JSON，只表示最终一次响应，不累计重试用量。读取历史单元格时不重新解析其 JSON。
- 新响应的 `created` 按数值 Unix 秒转为北京时间（固定 UTC+8），`response_created` 仍为文本，例如 `1791947560` 保存为 `"2026-10-14 11:12:40"`，小数秒不保留。缺失或 null 时为空，不影响回答成功判断；`0` 是有效时间戳。
- `created` 非数值（包括布尔值和数字字符串）或超出可转换日期范围时，本次响应失败，在剩余请求预算内重试；若最终仍有此问题，该帖保存为 `"-1"`，同时将 `ai_response_content/reasoning_content/usage_json/response_created` 全部写空，覆盖同一任务的旧结果，并记录失败原因。其他失败继续保留最后一次可安全提取的结果。具体错误优先级见 [关键规则](../rules/KEY_RULES.md#response_created-保存北京时间文本)。
- `response_created` 不参与日期筛选，不替换原索引时间。已完成的历史记录不会自动转换或清空，原来的时间戳文本仍允许读入并跳过。
- 原输入 `text`、`user_name` 和索引在任务处理期间保持不变；后续新增任务按同一字段要求完整创建。

## 读取普通列原值与全表摘要

运行端检查原索引、九列结构与读取日期范围，不检查数据库普通列的类型、NaN、None、pd.NA、空字符串、状态枚举、摘要格式或历史结果完整性。不自动清洗或修复。初始化脚本的源输入检查保持原样。

选择端按字符串状态工作：0 进入待处理，9/-1 按 batch_size 恢复为 0，1 跳过；其他值原样保留，不自动选中。新写入仍要求字符串，空值写空字符串。成功保存后更新当前内存快照，分段结束按状态统一汇总，不额外读库。

例如已完成行的旧正文为 NaN，加载阶段不报内容校验错误，也不自动重做；若后续事件导入实际解析该正文，仍可能在解析时失败。未知状态属于总数，但可能不进入任何约定状态统计。

首次实际认领前，用 common.store.read_stage_hashes 调用 `cli.read(task_path, start_time='', end_time='', columns=['config_hash'])`，按列核对全表 config_hash，范围外摘要也参与；本次运行只计算和读取一次，跨月复用。返回 DataFrame，直接取 config_hash 列原值；初始空字符串不参与比较，其他原值与当前摘要不一致则停止，不补旧摘要。读取失败或返回缺列时停止，不回退整表读取；全部完成时不调用该接口。详见 [Store 共用方案](../history/STORE_REUSE_PLAN.md)。
