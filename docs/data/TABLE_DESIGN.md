# 任务表字段

任务表每帖一行，保存登记时的帖子输入及最新一次完整处理的结果。处理规则见 [关键规则](../KEY_RULES.md)，项目关系见 [项目总览](../../project_overview.md)。

## 索引与字段

表格使用两层索引，名称和顺序固定为 `date`、`id`，即 pandas 的 `MultiIndex`。普通列恰好为下列九列，所有普通单元格均为字符串；没有结果时使用空字符串，不能使用缺失值。

| 索引或字段 | 含义 | 初始化值 |
| --- | --- | --- |
| `date`，索引第 1 层 | 源帖子的原始时间，对应原帖 `created_at`；保持原类型、时区和精度。 | 源值。 |
| `id`，索引第 2 层 | 帖子的唯一、非空白字符串 ID，与 date 共同定位行。 | 源值。 |
| `config_hash` | 提示词模板及 AI 调用参数的 64 位小写十六进制标识。 | 空字符串。 |
| `text` | 登记时的帖子正文。 | 源值。 |
| `user_name` | 登记时的用户名，仅作记录和保存核对。 | 源值。 |
| `status` | 未处理、处理中、成功或本次最终失败。 | `"0"`。 |
| `ai_response_content` | 最终 AI 回答正文，保留原文。 | 空字符串。 |
| `reasoning_content` | 最终推理文本，保留原文。 | 空字符串。 |
| `usage_json` | 最终响应 `usage` 的标准 JSON。 | 空字符串。 |
| `response_created` | 最终响应 `created` 的字符串表示。 | 空字符串。 |
| `error_message` | 最终失败原因，最多 512 个字符；成功时为空。 | 空字符串。 |

`date` 不能缺失，复合索引、ID 和列名均须唯一，同一 ID 不能对应多个日期。日期不会被处理时间或 AI 生成时间替换。

初始化源表需要字符串 `text`、`user_name`，保留原两层索引；其他源列不写入任务表，无需提供 id 普通列。仅有旧 `username` 的源表不满足要求，任务表也不接受额外的用户名列。

## 状态含义

| 保存的值 | 含义 | 下次运行读取到该任务时 |
| --- | --- | --- |
| `"0"` | 等待处理。 | 保持 0。 |
| `"9"` | 已标记开始处理，正在请求、等待重试或等待保存结果。 | 重置为 0。 |
| `"1"` | 成功结果已保存。 | 保持 1，跳过。 |
| `"-1"` | 本次最终失败及其原因已保存。 | 重置为 0。 |

状态只是本地任务记录。`"9"` 不证明请求已发送，`"1"` 不证明回答的业务判断正确。

## 数据有效性

- `config_hash` 为空或符合 64 位小写十六进制格式；成功记录的标识和非空白正文必须存在，错误原因必须为空。
- 非空的 `usage_json` 必须是标准 JSON，只表示最终一次响应，不累计重试用量。
- `response_created` 缺失或为 null 时为空；字符串原样保存，其他 JSON 值编码为字符串。它不参与日期筛选，不转换单位或时区。
- 原输入 `text`、`user_name` 和索引在任务处理期间保持不变；后续新增任务按同一字段要求完整创建。
