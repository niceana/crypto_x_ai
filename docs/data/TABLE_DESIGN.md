## 目的与范围

ai_tasks 每帖一行，保存单帖输入、提示词与 AI 参数的配置摘要、四值状态，以及最新最终正文、推理、token 用量、接口生成时间和失败原因。原始帖子仍由已有流程维护，不保存每次尝试、重试计划或其他接口诊断元数据。

任务表使用名称、顺序为 date、id 的双层 MultiIndex。date 直接沿用源 cli 日期索引，与原帖 created_at 一致，原值、类型、时区和精度不变。id 为原帖唯一非空白字符串；普通列均为字符串。

## 创建、读取与处理顺序

一次性初始化覆盖现有全部帖子，以源 date/id 为索引，保存 text 正文和 user_name 记录，状态为 0，config_hash、结果与失败原因均为空字符串。不读取 AI 配置、不计算摘要。任务模块直接根据源构造完整任务表并调用一次接入回调，由接入回调先使用 cli.register(task_path, "timeseries", "") 注册目标，正常返回后用一次 cli.write 写入；调用方使用已知尚未创建的新目标，整个初始化链不读取或核对目标，不准备占位空表。注册和完整写入均正常返回才报告成功；注册失败不执行写入，注册成功但写入失败可能保留目标资源及部分数据。失败后由用户核查注册状态和内容，使用尚未注册的新目标或按真实客户端规则处理原目标后再重跑，不续写、不补缺，也不自动清空或注销。写入失败可能残留部分数据，本规则不承诺数据库事务原子性或拒绝覆盖。

以后新增帖子时，由现有数据新增流程直接创建对应的完整 0 任务，沿用源 date/id、text 和 user_name，config_hash 与五个结果字段为空，并保证每帖全表唯一。新任务创建不需要读取 AI 配置。工具不提供新增写入封装、补登记或查重读取；worker 不补建任务。

worker 将总起止范围按自然月拆为互不重叠的左闭右开片段，通过 cli.read(task_path, start_time=当前段起点, end_time=当前段终点) 按 date 限制实际读取。每月依次读取、处理、写回，全部保存确认后释放该月数据，再进入下月；不读入或拼接全年 DataFrame。主线程只保有当前月 DataFrame，从当前选中行取原 (date, id) 键和 text；任务键只关联作业及结果，AI 消息只含提示词和 text，不发送 user_name、任务键、整表、状态或历史结果列。真实 cli 的边界与时区由接入层适配，未设置总日期两端时保留单次全表读取。

每月首次读取后将本段全部 9/-1 重置为 0，每段只执行一次，不计算或覆盖摘要；1 和本段外任务不改动。选择 0 后，按本次固定配置快照计算 config_hash，与 status=9 同一次更新确认后才调用 AI。明确网络传输故障与全部 5xx 的中间失败和重试只在内存中，重试期间状态保持 9，沿用同一摘要和请求配置；两者共用本帖尝试预算，不保存中间响应或次数。

成功后在一次更新中回填状态 1、ai_response_content、reasoning_content、usage_json、response_created，并将 error_message 清空。最终失败在一次更新中回填 -1、最后失败中可用的正文、推理、用量、接口生成时间和可读原因；没有或缺失的结果字段明确写空字符串。

其他非 2xx 响应（包括 400、401、403、429）或预算耗尽后仍返回 5xx 时，worker 停止，并尽力保存触发任务的 -1 与最终失败原因，以及其他已完成结果。没有最终响应的已认领任务保留 9，未认领任务保持 0；停止不伪造失败结果。明确网络传输故障耗尽预算时只保存该帖最后失败，继续其他任务；具体条件见运行规格。

本次新产生的 -1 不再次入队，不因切换月份而重置，下次 worker 读取到时重置。每月无待处理、在途或待保存结果后可进入下月；空月不提前结束整个运行。全部月份完成后才声明本次总日期范围已处理完，输出所有月份本次成功、失败数量之和。停止或异常后不进入后续月份。

## 按需列更新与索引保持

worker 更新调用 cli.update_by_index(path, df1)。df1 只包含当前批次的原 date/id 复合索引和本次需更新的列；未提供的列保持原值。初始化提交完整任务表，现有流程创建新任务时也提交完整新行，不与 worker 按需列更新混用。

- 启动重置：仅提交 status="0"。
- 登记处理中：共同提交 status="9" 和 config_hash=本轮配置摘要。
- 保存最终结果：提交 status、ai_response_content、reasoning_content、usage_json、response_created、error_message 六列，覆盖上次结果，包括用空字符串清除本次缺失字段。

df1 的索引从当前月原读取 DataFrame 对应行取得，不转换日期，不重算索引，不复制完整输入或全部历史结果列。更新异常先核对原复合键和帖子输入未变；config_hash 未提交时须保持原值，认领更新提交了该列时则允许变为本轮摘要，按提交列预期值核对，不能视为输入冲突。确认后在当前月原 DataFrame 同步这些列，不构造全表更新副本。

例如原索引为 (2019-06-03 10:20:30, "123")，初始 status="0"、config_hash=""；认领时提交这个索引、status="9" 和本轮 64 位摘要。成功回填仍用原索引，提交六个终态列，不再次改摘要；不能把 date 改成整天日期或当前处理时间。

## 日期范围与任务完整性

start_time/end_time 按 date 筛选，date 与原帖 created_at 一致且不随更新变化。工具约定左闭右开，接入层根据真实 cli 语义适配：右端点多读可排除，左端点漏读必须先修正读取参数，不能靠删行补救；适配不改变原索引。异常读回始终沿用当前分段相同参数，按原复合键核对。

例如 [2021-01-01, 2022-01-01) 正常读 12 次，每次完成该月后进入下一月；2021-02-01 00:00 只属于二月，2022-01-01 不在范围内。[2021-01-15, 2021-03-10) 则读三个部分或完整自然月份。月间只汇总标量计数，不保留此前月任务表或结果表。

初始化必须覆盖现有全部帖子，不使用局部 worker 日期范围筛选源数据。后续新任务的完整创建和每帖唯一性由现有数据新增流程保证，不通过覆写已存在行的状态和结果来创建新任务。worker 只验证实际读取的任务，不从源库核对缺失帖子。

## 配置摘要与最终结果口径

config_hash 是本轮原始提示词模板和 AI 调用参数的 SHA-256 摘要，不是配置正文。任务创建时为空，仅认领时计算并与 9 共同保存，用来记录本轮准备使用的配置；启动读取、恢复和已成功任务不计算或改写摘要。实际 prompts 和 api.payload 保存在 YAML，摘要不包含 URL、认证、日期范围、帖子内容、运行参数或响应解析版本，详细口径见 [配置规格](../modules/config/IMPLEMENTATION_SPEC.md)。仍要求改提示词或 AI 参数使用新任务表，成功任务不会自动重跑；只在认领时核对当前分段已有非空摘要，不承诺启动全表检查。

ai_response_content 与 reasoning_content 分列保留原文。error_message 直接保存最后最终失败的接口说明或实际异常、解析失败原因，可附实际 HTTP 状态，最多 512 字符；没有具体说明时使用简单兜底，不建立内部错误码或分类文案，规则见 [响应规格](../modules/response/IMPLEMENTATION_SPEC.md)。运行模块直接依据 HTTP 状态或异常类型停止时，触发任务仍保存 -1 和具体原因，不增加状态或诊断列。usage_json 保存接口最终响应 usage 的标准 JSON，保留接口实际提供的 token 字段及嵌套明细，不补缺或自行推算。response_created 保存同一最终响应顶层 created 的原值：字符串原样保存，其他非 null JSON 值编码为字符串，不猜测时间单位、转换时区或替换为本地处理时间。两字段缺失或 null 时为空。

例如接口提供 usage={"prompt_tokens":120,"completion_tokens":40,"total_tokens":160}，则该对象原样编码到 usage_json；若 created=1700000000，response_created 保存为 "1700000000"，示例不规定其时间单位。usage_json 只反映最终一次响应，不累计重试，不代表本帖所有尝试的总 token 用量；没有响应的最终失败两字段为空。正文本身若是业务 JSON，仍原样保存；进一步拆业务字段须先确定业务输出结构。启动重置和登记 9 可保留旧结果，但旧结果不参与调度或恢复。

响应模块只返回 success 布尔值、HTTP 状态及必要结果；success 用于映射 1/-1，HTTP 状态和实际异常类型直接用于重试或停止，两者不落库。不生成 error_code 或 response_status 等内部细分类；choice 的 index、finish_reason、refusal 仅用于解析判定。任务表不保存上述诊断字段，也不保存 response_id、response_model、response_object、refusal_json、raw_response 或整包 result_json。

## 字段汇总

| 字段 | 含义与初始值 |
| --- | --- |
| date（索引第 1 层） | cli 原始日期索引，与原帖 created_at 一致，类型及值不变。 |
| id（索引第 2 层） | 原帖唯一字符串 ID，与 date 共同定位行。 |
| config_hash | 本轮提示词模板和 AI 调用参数的摘要；初始为空，认领时与 9 共同写入，恢复时保留原值。 |
| text | 登记时的帖子正文快照，唯一的任务 AI 输入字段。 |
| user_name | 登记时的用户名快照，仅用于表内记录和更新核对，不发送给 AI。 |
| status | "0"、"9"、"1"、"-1"；初始为 "0"。 |
| ai_response_content | 最新最终 AI 返回的回答正文，来自所选 message.content；初始为空。 |
| reasoning_content | 最新最终推理文本；缺失或初始为空。 |
| usage_json | 最终响应 usage 的标准 JSON，用于查看 token 用量及明细；缺失或初始为空。 |
| response_created | 最终响应 created 原值的字符串表示，用于查看接口生成时间；缺失或初始为空。 |
| error_message | 最新最终失败的简短可读原因，最多 512 字符；成功或初始为空。 |

仅以上两个索引层及九个普通列，不增加任务次数、处理时间或其他诊断列。源、核心输入和任务表都使用 user_name；仅有旧 username 的任务表以及同时具有两个用户名列的任务表均不符合任务表契约。已有业务表和外部新任务创建流程需由调用方同步字段，不自动迁移、重建或覆盖。原帖 created_at 已由 date 索引承载；response_created 是 AI 接口时间，不参与读取范围或状态恢复。

## 四值状态汇总

| 状态 | 运行行为 | 下次读取到并启动 worker |
| --- | --- | --- |
| "0" | 唯一的新作业选择状态。 | 保持 0。 |
| "9" | 请求、内存重试或结果待保存。 | 重置为 0。 |
| "1" | 最终成功结果已保存。 | 保持 1，跳过。 |
| "-1" | 本次最终失败原因已保存。 | 重置为 0。 |

例如第一次请求失败、第二次成功，状态为 0→9→1，只保存第二次成功结果；本次全部失败则为 0→9→-1，下次读取到该任务时再重置为 0。停止 worker 留下的 9 同样在下次读取到时恢复。

## 一致性、成本与验证

只支持单 worker。停止整个 worker 是用户停止处理的唯一方式；没有按任务取消状态或入口。旧 worker 结束后才能启动新 worker。已执行但未保存的远端请求可能在重启后重复调用。

认领一次更新提交 status/config_hash 两列，终态一次更新提交六列；由用户验证真实 cli 会保留未提交列，以及各次单行多列写入的一致性、异常可见性，目前未验证。worker 更新失败重写原索引上的同一批列，不重新请求 AI。初始化写入失败不进入该更新重试流程，由用户清空目标后重新初始化。

按自然月限制读取 DataFrame 的规模；去掉原始响应和诊断元数据可减少保存内容，单月仍可能较大。真实 cli 与左闭右开/时区适配由用户验证，源帖完整性、后续新任务创建和跨月 ID 唯一性由现有数据流程保证。

验证要求包括创建任务时摘要为空、认领才计算且与 9 共同保存、恢复不改摘要、认领异常允许预期摘要变化、按需列更新不会改动未提交列、状态和结果一次保存、成功清空旧错误、无响应失败清空旧正文/用量/接口时间、usage 原值保存且不累计重试、response_created 不改变帖子 date、原复合索引不变、AI 消息只含提示词与 text、user_name 仍保存并参与异常核对、响应 success 只映射为 1/-1、不增加错误码或分类列、失败直接保存具体原因、网络与 5xx 中间重试不改 9、重试只保存最终结果、其他 HTTP 失败及预算耗尽的 5xx 停止后仍保存已完成结果、未完成任务保留 9，以及部分写入核对；验证一年正常读取 12 段、月初不重不漏、月末结果确认后才读下月及跨月总统计。已使用假 cli 与模拟 HTTP 完成验证，具体记录及限制见实现自查；未操作业务数据。
