# 事件去重分析表

2026-10-16 已按用户确认新增 embedding 一列保存向量，不再保存到 SQLite。事件去重分析表尚未创建，初始化直接采用新结构，不增加旧表迁移；保存与阈值规则见 [调整方案](../plans/EMBEDDING_TABLE_STORAGE_PLAN.md)。

更新日期：2026-10-16。round1帖子事件提取表保持不变，本表由固定的round1事件提取成功结果展开。

## 索引和字段

索引为 `(date, record_id)`，普通列共 14 个，总计 16 项。普通列都以字符串写入；关联字段逻辑上的 `null` 在表中写为空字符串 `""`，发给 AI 时恢复为 JSON `null`。回答列内部的缺失 usage 使用 JSON `null`。

| 项目 | 用途和初始值 |
| --- | --- |
| `date`（索引） | 原帖子完整发布时间，原样沿用round1事件提取索引，不转换时区，不截到日期。 |
| `record_id`（索引） | `source_post_id:event_index:asset`；事件序号从 0 开始。全表唯一。 |
| `event_id` | 事件组建档记录的 `record_id`。初始为空；new 使用自己的 ID，update/repeat 继承匹配组 ID。 |
| `event` | round1事件提取事件正文。导入后不修改。 |
| `asset` | 单个代币，去掉首尾空白并转为大写。导入后不修改。 |
| `source_post_id` | 原帖 ID 的字符串形式。导入后不修改；round1事件提取原 ID 类型不变。 |
| `event_relation` | 初始为空；完成后为 new/update/repeat。模型正常 uncertain 转为 new。 |
| `new_information` | update 的非空变化说明，包含必要的此前已知状态、本次新增或修正、变化后的状态及条件，供第三轮独立理解本次变化；旧状态来自匹配组历史，新事实来自当前 event，缺失处不补造。其他关系为空字符串。 |
| `round2_ai_response` | 第二轮 AI 原始回答和调用信息的 JSON 字符串，初始为空；程序自动判新时为空。 |
| `round3_ai_response` | 第三轮 AI 原始回答和调用信息的 JSON 字符串，替代五个独立影响列；初始为空；repeat 由第三轮复制有效历史响应。 |
| `round2_status` | round2事件去重归组状态，初始为 `"0"`。 |
| `round2_config_hash` | 本阶段提示词和 AI 请求参数的 SHA-256 摘要，认领时与round2事件去重归组状态一起保存；自动判新也绑定该配置。初始为空。 |
| `round3_status` | round3事件影响分析状态，初始为 `"0"`。 |
| `round3_config_hash` | 本阶段 AI 配置摘要，认领时与round3事件影响分析状态一起保存；repeat 不调用 AI，复制来源记录的第三轮摘要。初始为空。 |
| `error_message` | 最近一次最终失败原因，最多 512 字符，初始为空。成功后清空，不累计历史错误。 |
| `embedding` | 初始为空字符串；round2事件去重归组准备阶段保存 JSON 对象，包含 model、model_version、config_hash 和模型已归一化的 vector。只编码本行 event，保留模型返回数值，直接计算内积供相似度检索复用，不发送给关联或影响 AI。 |

两个状态字段分别使用 `"0"` 待处理、`"9"` 已认领、`"1"` 本阶段完成、`"-1"` 最终失败。运行逻辑只匹配这些字符串；读回的数值 0/1 不做类型校验，也不会自动当成对应字符串状态。

例如原帖 `(2018-01-01 12:12:12, 22222222)` 返回两个事件，第一个涉及 ETH 和 LEND，第二个涉及 ETH，则展开为 `22222222:0:ETH`、`22222222:0:LEND`、`22222222:1:ETH`。三个索引都保留原帖时间。

## 保存与检查

初始化时给出全部普通列和初始值。后续通过 `update_by_column` 只更新当前阶段的列，按原索引整行排序；不保存round2事件去重归组输入、候选列表和检索得分。

Embedding 每批生成并验证后，只提交原索引和 embedding 一列，使用共用存储重试；保存失败不重复请求向量。保存成功后才认领关联任务。对象示意为 `{"model":"bge-m3","model_version":"bge-m3-v1","config_hash":"实际64位SHA-256","vector":[0.6,0.8]}`，二维向量仅为展示，实际维度以服务响应为准。config_hash 包含服务地址、模型、版本及编码规则，不含 event；相同配置各记录一致。标识匹配才复用；空字符串或有效对象的标识不匹配时重新生成并覆盖本列，格式损坏时停止。

模型输出已经归一化，程序只检查范数与 1 的绝对误差不超过 1e-5，不缩放分量或转成 float32。保存及重启复用均保留响应数值，内存使用 float64 数组直接计算内积。编码规则标识已更新为 event-only-service-unit-f64-v3，以区分此前由程序归一化及转换为 float32 的保存规则。

默认 similarity_threshold=0.50；只提交组内最高余弦分数达到阈值的最多 10 组，不补足。无历史或所有组都低于阈值时保存 new，round2事件去重归组为 1、round3事件影响分析保持 0。阈值变更仅影响待处理关联，不自动重算已完成round2事件去重归组；更换模型时向量配置标识变化，不据此清空已有业务结果。event 沿用固定输入约定，人工修改时须清空对应 embedding 并确定关联及下游重算范围，配置摘要不检测文本变化。

new/update 关联完成后，两阶段状态为 `(1, 0)`。repeat 关联保存不写任何第三轮字段，初始状态同样为 `(1, 0)`；第三轮复制有效历史响应后才变为 `(1, 1)`。没有有效来源则第三轮为 `-1` 并记录错误。

round3事件影响分析认领时写自身状态和配置摘要；分析完成时只写 round3_ai_response、round3事件影响分析状态和共享错误字段，不更新关联结果、round2_ai_response 或round2事件去重归组状态。round2事件去重归组已经完成的行不会因round3事件影响分析失败而重新调用关联 AI。

读取普通业务列不执行历史内容质检：不检查 NaN、类型、空字符串、旧回答 JSON 或历史摘要是否缺失。9/-1 按 batch_size 恢复为 0，保留旧结果和错误，不推断成功、不修复历史 repeat。新 AI 输出仍校验业务格式；本程序新提交值仍须为字符串。实际用于检索的 embedding 另行解析并检查内容和维度，防止错用向量，不修改其他普通列。

round2事件去重归组与round3事件影响分析读取事件去重分析表保留原索引、14 列结构和日期范围检查，普通业务列值原样使用。round3事件影响分析保留 embedding 但不解析、修改或发给 AI。独立事件导入保留固定输入比较、索引去重与新行追加，不通用质检旧单元格，也不补写旧字段。详细顺序见 [运行规则](../rules/EVENT_RULES.md)。

2026-10-21 起，repeat 的第三轮回答原样复制有效来源的完整 JSON 及其配置摘要，五个调用信息键均保留源值，保存重试也不刷新 created；这些复制的 usage/attempts 不代表本条新增模型调用。本轮实际 HTTP 请求汇总不增加。源响应需通过五字段业务校验。旧版已标第三轮完成但回答为空的 repeat 不自动回填；需回填时将第三轮状态置为 0 后重新运行。

## 两轮 AI 回答的保存口径

2026-10-16 用户确认合并第三轮保存列，并将调用信息放入各轮回答 JSON。两列结构相同，均恰好包含以下五个键，不保存推理文本：

| JSON 键 | 保存内容 |
| --- | --- |
| `ai_response_content` | 最后一次响应可安全提取的 AI 正文，保留原文字符串；未取得正文时为 `""`。第三轮正文仍须包含 direction、materiality、execution_stage、persistence、materiality_reason 五个非空文本字段，校验不因合列而放宽。 |
| `usage` | 最后一次响应的完整 usage 对象；缺失为 `null`，不累计前面重试的用量，也不回退使用更早响应。 |
| `response_created` | 接口返回的 created 按既有解析规则转换为北京时间文本；缺失为 `""`。 |
| `attempts` | 本任务本次运行实际发起的 HTTP 请求次数，包含首次请求和重试；存储重试不计入。 |
| `created` | 每次向数据库提交该批结果前取得的当前北京时间，格式 `YYYY-MM-DD HH:mm:ss`。同批结果共用时间，存储重试时重新取时，保存成功那次提交前的值；这不是数据库服务器返回的事务提交时间。 |

例如第三轮正文为 `{"direction":"利好","materiality":"中","execution_stage":"已完成","persistence":"长期","materiality_reason":"减少流通供给"}`，实际仍原样保存在 round3_ai_response 的 ai_response_content 字符串内。后续研究先解析回答列，再解析正文 JSON，即可展开五个影响字段。

第二轮 AI 正文现为 event_relation、matched_candidate_id、new_information 三字段，matched_candidate_id 使用当前请求内的 E1、E2 等短编号。程序先校验并映射回真实 event_id，数据库 event_id 列继续保存真实组 ID；round2_ai_response.ai_response_content 保留 AI 原始短编号，不改写正文。不新增列、映射表或持久状态，旧回答正文也不迁移；研究时优先使用该行 event_id，不把原始回答中的 E1 当作跨请求可用的组 ID。

例如第一次 AI 输出格式错误、usage.total_tokens=100，第二次成功、usage.total_tokens=13，则保存第二次原始正文、usage.total_tokens=13、attempts=2，不保存 113。若 18:20:30 提交失败，18:20:35 重试成功，created 保存当天 `18:20:35`，attempts 仍为 2，接口返回的 response_created 也不因存储重试而改变。

第二轮合法 uncertain 的正文仍保存 uncertain，业务 event_relation 按既有规则保存 new。程序自动判新不伪造 AI 回答，round2_ai_response 为空；repeat 不调用第三轮模型，由第三轮处理程序复制同币同组严格此前最近一条有效响应及其配置摘要，响应 JSON 原样保存。已完成历史结果不会为了补回答而重调 AI。

调用或正文校验最终失败时，同次保存 `-1`、错误和最后一次可安全提取的回答及调用信息；网络失败无响应时正文和 response_created 为空、usage 为 null，仍保存 attempts 和 created。旧回答由本次最终结果覆盖，不能作为成功业务结果使用。中断取消且没有最终结果时仍保留状态 9，不伪造回答或落库时间。状态恢复及认领不改回答和 created。

存储失败不重新调用 AI；重试保持原记录键、正文、usage、attempts、状态和错误，只重新取得 created。数据库写入确认后，内存使用实际提交的整批值同步。沿用事件表尚未创建的已确认前提，本次不增加旧结构迁移；若另有旧表，不能直接作为新结构读取。

导入程序负责round1事件提取结果校验、事件展开、映射和追加；独立导入入口另做严格的固定输入核对。round2事件去重归组与round3事件影响分析以本表已有记录为任务，按阶段状态处理，不再展开round1事件提取或比较导入覆盖。第二轮只使用 event 和候选历史，不读原文；第三轮的 AI 请求只使用本行 asset、event、new_information，不读取原帖；repeat 另读必要的历史响应列用于复制。日常漏导任务通过再次运行覆盖相应帖子日期范围的 main.py 补齐；历史输入或映射变更另行确定重算范围。

main.py 自动导入按以下步骤使用本表：

1. round1事件提取按本次配置的帖子发布时间范围读取round1帖子事件提取表。读取时已经 status="1" 的帖子跳过 AI，直接保留已保存的 ai_response_content；其他帖子按原规则处理，成功后保存。
2. round1事件提取正常结束后，从这些内存数据的 ai_response_content.events 生成任务，不重读round1事件提取。若本次读取时没有帖子已经 status="1"，只查本表元数据，表存在就直接追加新任务。
3. 若本次读取时有帖子已经 status="1"，则读取一次整张事件去重分析表，检查索引结构和唯一性，将这些帖子和本次新成功帖子生成的任务一起按 (date, record_id) 核对。索引不存在才追加完整初始字段；索引已存在则跳过，不比较或修改其业务字段，保留已有状态、关联和分析结果。

读取整张目标表不会使范围外帖子参与导入；不设置日期限制时round1事件提取按全表处理。目标明确 DataNotFound 时 register/write，空事件和已注册空目标仍可补齐结构。导入失败保留round1事件提取结果；再次运行同一范围时，按已保存的 ai_response_content 生成任务并核对缺少的索引，不重调已成功帖 AI，不增加导入状态字段。正常直接追加以 ID 稳定唯一、成功状态不人为回退及单程序写入为前提，人工修改后须使用独立入口核查。


## 配置摘要与续跑

两轮摘要分别保存，不互相覆盖。本程序新生成摘要为 64 位小写十六进制，初始为空；repeat 正常路径复制来源记录的第三轮摘要。读取历史数据不校验摘要格式，也不根据成功状态要求补齐摘要。

认领提交该轮状态与摘要两列。失败和恢复保留摘要；当前阶段继续处理前比较同轮全表已有非空摘要与当前配置，冲突停止，不能静默换模型或提示词。两轮配置可以不同。全部已完成时不要求当前配置可加载，也不为核对结果重新调用 AI。

初始化 resume 不补摘要列或缺失单元格；缺少必要列仍报结构错误，普通单元格原样保留。实际使用固定输入时仍进行业务比较。准备认领时统一调用 `cli.read(result_path, start_time='', end_time='', columns=[hash_column])` 比较全表本阶段摘要，从返回的 DataFrame 中取列原值；读取失败或返回缺列时停止，不以整表读取代替。详见 [Store 共用方案](../history/STORE_REUSE_PLAN.md)。
