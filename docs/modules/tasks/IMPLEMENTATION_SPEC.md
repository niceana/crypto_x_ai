## 1. 目的与范围

维护每帖一行任务，负责一次性初始化、启动恢复、选择 0、标记 9，以及共同保存最终状态、正文、推理、用量、接口生成时间和失败原因。后续新帖任务由现有数据新增流程创建，不属于本模块。

仅有 0、9、1、-1 四值状态，不保存调用次数、恢复时间、响应分类或机器错误码，不依据旧结果恢复状态。重试由运行模块在内存执行。

## 2. 输入、接口与所有权

worker 每段使用 TaskStore(config, cli, task_path, start_time=None, end_time=None)。config 是运行模块启动时固定的配置快照；cli 是调用方已经提供的唯一同步客户端；task_path 是任务表数据标识，原样用于本段全部读取和更新。TaskStore 保留 cli、task_path 以及本段起止范围，不创建客户端、不导入 xdata 建立连接、不在月份或保存重试时替换客户端。起止范围由运行模块校验和分段。

cli 提供 read(task_path, start_time=YYYY-MM-DD字符串, end_time=YYYY-MM-DD字符串) → DataFrame 和 update_by_index(task_path, df1) 两个既有同步方法；无界读取只调用 read(task_path)。有界输入 start_time/end_time 为运行模块提供的 YYYY-MM-DD 字符串，按日左闭右闭，起止两日均包含全天；TaskStore 原样保存并传给 cli.read，读取时不再次解析或格式化。两端均为 None 时保留无界读取。只有范围校验内部根据截止日期计算下一日的日界线，见第 5 节；该辅助边界不传给客户端，也不改变保存的范围。cli 与 DataFrame 仅在调用入口线程串行使用，客户端不交给网络线程。正常 update_by_index 返回代表本批指定列更新已确认；异常后的读回与重试见第 8 节。

删除 TaskCallbacks 的类定义以及 ai_batch 包中的导入和导出，移除 worker 对 callbacks 属性、读写闭包和旧构造签名的依赖。运行、任务测试及测试辅助客户端统一传入 cli 和 task_path，不保留旧接口兼容层。初始化所需的类型、函数和包导出保留。

initialize_tasks(source_df, write_tasks) 返回 InitializationSummary(total, written)，正常返回时 total=written=源帖子数量。初始化只接收全部源帖子与完整写入回调，不接收目标读取回调或占位表，不接收配置路径、不加载 AI 配置、不计算 config_hash。write_tasks(df) 由调用方提供，负责初始化目标准备和完整写入；本模块只调用一次该回调并提交本模块构建的完整初始化表。xdata 初始化接入提供的回调先使用用户确认的 cli.register 注册目标，再执行一次 cli.write(task_path, df)；具体注册参数与失败处理见 [初始化接入规格](../initialization_entrypoint/IMPLEMENTATION_SPEC.md)，其他直接调用方仍自行管理目标准备与持久化；该初始化回调与完整建表接口本次保留。调用方提供新的目标，模块不读取或核对实际目标。不保留旧三参数签名的兼容入口，仓库内调用同步迁移。不提供任务追加、新帖登记或补登记接口。

TaskKey 为原 (date, id) 元组。date/id 是名称、顺序固定的双层 MultiIndex，date 保持 cli 原读值、类型、时区和精度，id 与普通列均为字符串。交给运行模块的作业输入只有原 TaskKey 和不可变 text 快照；任务键只用于内部关联，配置模块仅接收 text。user_name 保留在任务表供记录与更新核对，不进入网络作业或 AI 请求。主线程保有读取的 DataFrame，更新只构造当前批次的指定列，不复制全表或完整行作为更新对象。

更新前保留 pending_patch：原批次索引与本次提交列的副本；确认后仅在内存当前分段 DataFrame 同步这些列，并清除待确认更新。中断继续传播，收尾保留未确认更新供核对。只支持一个 worker，现有数据流程创建新任务与 worker 写入由调用方协调。每段初次读取形成自己的快照，不轮询或回读已完成月份；尚未读取月份以实际进入时的读取结果为准。

## 3. 总体执行顺序

初始化：校验全部源帖子及原索引 → 构造全部完整 0 任务且 config_hash 为空 → 调用一次 write_tasks 完成目标准备与完整写入 → 回调整体正常返回则报告成功；任一阶段抛错则终止并报告失败。xdata 接入回调的准备动作是先注册目标，注册失败不写入；写入失败可能保留注册资源或部分数据，由调用方按真实客户端规则处理。核心不识别或单独执行注册阶段。

当前分段：保存 cli、任务路径和当前闭区间日期字符串 → 原样传递边界字符串并读取 → 校验完整任务表及包含末日全天的分段范围 → 仅更新本段 9/-1 的 status=0 并确认 → 建立 0 队列 → 认领前计算本轮配置摘要并核对本段已有摘要 → 将选中任务 status=9 和 config_hash 一起更新并确认 → 取单帖原 TaskKey 和 text 交运行模块请求与内存重试 → 得最终结果 → 一次更新六个终态列并确认 → 继续本段剩余 0 → 返回本段统计。运行模块汇总标量统计并释放本段数据，再进入下一月。

每个分段初次进入时只重置一次，不在 worker 启动时先读取全部月份集中重置。月份区间不重叠，新产生的 -1 不在本轮其他月份重新入队，留到下次 worker 读取到时处理。

## 4. 一次性完整初始化

源输入必须为 DataFrame，并保留名称、顺序固定为 ["date", "id"] 的原双层 MultiIndex：第 1 层是 date，第 2 层是 id，不要求提供 date 或 id 普通列。直接使用既有 _validate_index(source_df) 校验源类型、索引结构及唯一性，再使用 _validate_strings(source_df, ["text", "user_name"]) 校验输入快照；校验通过后直接以 source_df.index 构造任务表并提取 text、user_name，不复制源表或重建索引。删除“单层 date 索引加 id 列”的转换分支，不提供其他输入格式的自动兼容。date 与源 created_at 的对应由源读取流程保证，不解析或重算 date。

非 DataFrame 输入由既有索引校验抛出 TaskValidationError("输入必须为 DataFrame")；单层索引、缺少层名、层名错误、层顺序为 ["id", "date"] 或层数错误，均抛出 TaskValidationError("索引必须为名称和顺序固定的 date/id MultiIndex")，不调用写回调。错误消息直接沿用既有校验，不新增另一套判断或错误文案。例如源索引为 (带时区日期, "post-1")，层名为 ["date", "id"]，普通列只有 text、user_name，即为合法输入；仅有 date 索引和 id 普通列的表也拒绝初始化。

id 是唯一非空白字符串，date 非缺失，text、user_name 是字符串，允许空字符串。同 id 重复输入即拒绝，即使 date 不同；索引字段若同时作为列提供，须与索引值一致。只保留原索引、用于 AI 输入的 text 和用于记录的 user_name，完整性由调用方保证。

源可以具有其他普通列，初始化只提取 text/user_name；同时存在 user_name 和额外的 username 时，读取 user_name 并按既有额外列规则忽略 username，不进行重命名或覆盖。缺少 user_name，即使存在 username，也由既有字符串校验抛出 TaskValidationError("任务缺少必要列")，禁止写入。user_name 非字符串时沿用该字段的字符串校验错误；重复列名仍由索引校验拒绝。源对象的列名、值、顺序及索引不改变。

初始化覆盖全部现有帖子，固定用于已知尚未创建目标的一次性建表。本模块不读取目标，不构造或校验占位空表，也不判断目标是否非空；实际写入已有目标时的行为由调用方写回调决定，不提供拒绝覆盖保证。目标路径和使用前提由调用方负责，不提供模式选择。

每条新行保存 text、user_name、status="0"；config_hash、ai_response_content、reasoning_content、usage_json、response_created、error_message 均为空字符串。不加载 AI 配置、不计算摘要、不渲染请求、不调用 AI，按源读取顺序一次构造完整表，再由一次 write_tasks 回调完成目标准备与完整写入；xdata 接入在回调内先注册目标，再通过一次 cli.write 写入，不分批追加、不逐行 concat。源帖子为空时仍写入同结构空表并返回 0。

例如源有一帖，原 date 为带时区的日期，id="post-1"、text="正文"、user_name="账户"，输出沿用同一个 date/id 键，保存相同正文和用户名、status="0"，其余六列为空字符串。源为空时仍须满足源索引和列的结构要求；写入的零行任务表是实际输出，不是入口准备的占位表。

初始化只有回调整体成功返回和异常失败两种输出，不返回部分成功统计，也不执行失败后的读回确认、自动重试、续写、补缺或清空。源校验或构造失败时不调用 write_tasks，因此接入回调的注册与写入均不会执行；目标准备失败也由既有异常传播和日志处理，不增加核心参数、注册客户端依赖或另一套异常分类。cli 抛错时即使部分数据已经写入，本次也判失败；用户先等待旧操作结束，核查目标注册状态与内容，使用尚未注册的新目标或按真实客户端规则处理原目标，再从全部源帖子重新运行。例如 50000 条写入中断后目标残留 20000 条，不能继续写余下 30000 条，须先处理原目标或选用新目标，再完整初始化 50000 条；不能仅清空数据就假设重复注册一定可用。本规则不是数据库事务保证。

以后新增帖子的完整 0 任务由现有数据新增流程负责创建，config_hash 同样初始为空，字段及原 date/id 必须符合任务表契约；全表帖子 ID 唯一性、创建完整性及失败处置也由该流程保证。本模块不读取源库查缺、不处理新帖双写或提供补登记入口。

## 5. 任务加载与启动重置

TaskStore 保存传入的 config、cli、task_path 和当前分段 start_time/end_time。运行模块已经完成日期检查与自然月划分，有界边界为 YYYY-MM-DD 字符串，起止同日有效；本模块不接受或转换 datetime 边界，不重复运行模块的起止检查。断点处的 store.start_time/end_time、分段读取日志和实际 cli.read 参数使用同一组闭区间字符串。帖子 date 索引仍保留原始时间、时区和精度。

初次读取与保存异常后的读回复用简单的 _read_segment：

1. 两端均为 None 时，直接调用 cli.read(task_path)。
2. 有界时，直接调用 cli.read(task_path, start_time=self.start_time, end_time=self.end_time)，不做类型转换、日期格式化或范围调整。
3. _read_segment 直接返回客户端 DataFrame。数据校验由调用它的加载或保存流程负责；读取失败原样传播，不按空表处理或重试。

例如当前分段为 [2017-01-01, 2017-01-31]，TaskStore 保存 start_time="2017-01-01"、end_time="2017-01-31"，读取日志和 cli.read 使用完全相同的值。不增加时分秒，不扩大客户端读取截止日期或筛选客户端返回行。日期范围的字符串表示只用于分段边界，date/id 索引不因此转成字符串或截去时间。

首次加载按实际执行顺序进行：_read_segment 读取 → _validate_tasks 校验索引、列与完整任务内容 → _validate_range 校验当前分段范围 → 建立内存状态。保存异常读回继续按第 8 节只校验索引、必要字段与提交列，不能把完整终态校验加入异常确认流程。

日期字符串格式及左闭右闭语义来自用户说明的 cli 契约。字符串不携带时区，范围校验使用原 date 索引与日期字符串比较；对于 DatetimeIndex，pandas 按原索引的时区解释日期字符串，不建立无时区 datetime 边界或转换索引。cli 的日历解释须与索引中的日期一致；真实截止日全天覆盖和稳定读回仍待接入验证。任务路径、原 date/id、排序和状态不因字符串表示而变化。

读取表须具有 date/id 双层索引，普通列集合必须恰好为 config_hash、text、user_name、status、ai_response_content、reasoning_content、usage_json、response_created、error_message；列顺序不作为读取合法性的条件，初始化输出顺序仍按上述九列。旧任务表仅含 username，或同时含 username 与 user_name，均沿用既有九列校验错误而拒绝读取，不自动兼容或迁移。复合键唯一，date 非缺失，id 为唯一非空白字符串；不接受同 id 不同 date 的多行任务。普通单元格均为 str，status 为四值；合法空范围仍保留相同结构。读取失败或目标不存在报错，不以空范围推断全表完成。

读取时不计算当前配置摘要，也不要求所有行预先填好 config_hash；仅校验其为空字符串或 64 位小写十六进制摘要，并收集本段已有非空摘要集合供认领时核对，避免每批反复扫描全段。状态 1 要求 config_hash 非空、ai_response_content 非空白且 error_message 为空，否则报数据不一致；非空 usage_json 必须是标准 JSON；response_created 不推算时间单位。状态 1 直接跳过，不为跳过任务计算或更新摘要。读取只检查当前分段的键和数据，全表及跨月份 ID 唯一性由现有数据流程保证。

完整任务校验后，_validate_range 按以下顺序验证范围：

1. 无界分段直接返回；有界分段取原 date 索引层，不改动或重建索引。
2. 将 end_time 用标准库 date.fromisoformat 解析为日历日期，加 timedelta(days=1)，再用 isoformat() 得到截止日的下一日字符串。这里只为范围核对计算辅助日界线，不更新 self.end_time、读取日志或 cli.read 参数，不增加日期类型兼容或时间格式解析层。
3. 用向量化比较确认全部 date>=start_time 且 date<下一日字符串。该判断表示起止两日均包含全天；不使用 date<=end_time，因为日期字符串与时间戳直接比较时只表示该日零点。按日历日期计算下一日，不给原时间戳固定加 24 小时，因此保留夏令时日的日历口径；不逐行提取日期、不筛选复制整张任务表。
4. 范围外记录抛 TaskValidationError("cli.read 返回了当前日期范围外的任务")，不静默删除；原 date 索引无法与日期字符串比较时，仍把 TypeError 转为 TaskValidationError("读取结果与日期范围的类型或时区不兼容")。日期运算受标准库和现有索引类型的可表示范围约束，超出支持范围的错误继续传播，不新增通用日期兼容。

例如 [2021-02-01, 2021-02-28] 的 cli.read 仍收到 end_time="2021-02-28"；内部核对的下一日为 "2021-03-01"。2 月 28 日零点、晚间及最后一纳秒均合法，3 月 1 日零点即越界；越界在任何更新或 AI 请求前失败。单日 [2021-03-14, 2021-03-14] 也包含当天全天，带时区索引按自身时区解释 3 月 15 日日界线。客户端漏读范围内记录不能仅靠返回结果检测，仍须在真实接入中复核末日覆盖。

上述校验通过后，建立原 TaskKey 到行位置的映射、已有非空摘要集合和本段已有成功数量，初始化本次成功/失败计数、active_keys、候选队列及 pending_patch。不累计其他月份的数据。

将本次范围内 9/-1 按不超过 batch_size 的批次，只提交原索引和 status="0"，其余列不进入 df1。全部确认后才取任务，1 和范围外任务不改动，不判断任务时间或旧失败类型。

旧 ai_response_content、reasoning_content、usage_json、response_created、error_message 可以保留到新的终态保存，不作为本轮响应或调度依据。例如 A 为 1、B 为 9、C 为 -1、D 为 0，启动后只处理 B/C/D；C 再失败留为 -1，范围外 E 不受影响。

## 6. 选择、标记与提取输入

按原读取顺序建立状态 0 的轻量 TaskKey 队列，不反复扫描全表。选取数量不超过剩余作业名额，排除 active_keys，保证每帖本次只有一个处理流程。

确认本批需要认领后才调用 config_hash(config)，输入为 worker 启动加载且本轮固定的原始提示词模板与 api.payload，不重新读取 YAML，也不把帖子正文填入摘要。按本段已有非空摘要集合核对：任一与本轮摘要不同即报配置冲突，不提交本批 9、不发 HTTP；摘要为空的待处理行允许认领。没有 0 的分段不触发此计算与比较。确认认领后将本轮摘要加入该集合。仍由调用方保证改提示词或 AI 参数时使用新任务表，本模块不先读取全年或范围外数据做配置检查。

标记 df1 仅含选中行的原 date/id 索引和 status="9"、config_hash=本轮摘要两列；同一次 cli.update_by_index 确认后才交网络模块。从选中行仅提取原 TaskKey 和 text，组成不可变单帖作业快照；运行模块保管任务键并只将 text 传给配置模块。user_name 不提取为作业输入，不复制输入全表，不把任务键、旧结果、config_hash 或任务状态送入 AI。同一批任务使用同一配置摘要，程序内重试沿用同一配置和 payload，不再次写摘要。

状态和摘要写入未确认不发 HTTP；确认后提交前退出留下 9 及本轮摘要，下次读取到时恢复。摘要说明该认领流程准备使用的配置，不证明远端已经收到请求。date/id 只在 TaskKey 中关联结果，不进入请求模板。

## 7. 最终状态与结果共同保存

运行模块每帖只返回一次最终 ParsedResponse，网络传输故障与 5xx 的中间重试结果不交本模块。只依据 success 布尔值生成最终状态：true 为 1，false 为 -1；success 和 http_status 不落库，也不将整包对象序列化。结果读取 ai_response_content、reasoning_content、usage、response_created、error_message，失败原因直接沿用响应契约，不另行生成内部错误码或分类文案。usage 非 null 时以标准 JSON 编码为 usage_json，否则为空；response_created 为字符串时原样保存，其他非 null JSON 值编码为字符串，null 为空。不累计重试用量，不解释 created 的单位。

终态 df1 仅含原批次 date/id 索引及 status、ai_response_content、reasoning_content、usage_json、response_created、error_message 六列。成功为 1、最终正文/推理/用量/接口时间和空错误；失败为 -1、最后响应中可用的相应字段及可读原因。没有或缺失的结果明确填空字符串，不能省略这些列而留下旧值。

检查六列均为字符串且可 UTF-8 编码，usage 使用标准 JSON 编码并拒绝非有限值。status 和结果通过一次 cli.update_by_index(task_path, df1) 共同保存，批次可混合成功失败，不另分结果与终态阶段。不提交 text、user_name、config_hash 或其他列，不构造完整行或全表更新副本。

仅在该键六列确认后释放 active_keys，并增加本次成功或失败数。存储故障不是新的 AI 失败，不重新调用 AI。只保留本次最新最终结果；例如第 1 次请求失败、第 2 次成功，只回填第 2 次正文/推理/用量/接口时间和 1，不把第 1 次用量累加。

## 8. 保存异常与核对

每次更新开始前，若已有 pending_patch 未确认，则抛 BatchPersistenceError 拒绝叠加另一批更新；否则保留本次指定列更新的深副本作为 pending_patch，并以另一份副本调用 cli.update_by_index(task_path, df1)，避免客户端改动待确认快照。正常返回后，仅同步当前内存表的已提交列并确认对应键，不额外读回。

update_by_index 抛普通 Exception 时，保留原 pending_patch，通过同一 _read_segment、cli 和 task_path 读回。初次读取与异常读回都原样使用 TaskStore 保存的同一组年月日字符串，无日期转换；无界只传路径，当前 start_time/end_time 固定到本段结束，不读取总年份、不重新创建客户端。随后依次核对：

1. 校验读回索引结构、唯一性及 date 索引层的 dtype 与原快照一致，包括时区和精度；通过第 5 节同一 _validate_range 核对包含截止日全天的当前闭区间，再校验 text、user_name、config_hash 及本次提交列存在且均为字符串。按原 TaskKey 定位；读回失败、索引损坏、日期类型变化或原键缺失则停止，抛 BatchPersistenceError 保留未确认更新，不能用另一 date 的同 id 行代替或追加。月末晚间原键必须能读回，次月月初记录仍属于越界。
2. 先核对原 date/id、text、user_name 不变，发现冲突立即停止。例如原 user_name="账户A"，读回同一键却为 "账户B"，不能确认该更新。读回必须存在 user_name，不以 username 替代。config_hash 不属于本次提交列时须与更新前一致；认领批次会提交 config_hash，允许从旧值或空值变为预期摘要，改按下一步的提交列核对，不能误判为输入冲突。
3. 再仅比较本次提交列，值均等于预期则确认该键；无需其他未提交结果列与某份完整行副本相同。未确认键保留同一组待更新列。
4. 已确认键先同步内存并从 pending_patch 移除；全部匹配则清空 pending_patch 并结束，不额外重写。单 worker 前提下，仅重写尚未确认键的同一组列，仍直接调用同一 cli 的 update_by_index，不发 HTTP。storage_max_attempts 是本批总更新调用次数上限，包含首次；未确认且仍有预算时等待 storage_retry_seconds 后重试，读回不单独消耗更新次数。最后一次更新抛错但读回全部匹配也可确认。
5. 更新预算耗尽且仍未确认，或读回核对本身失败时，抛 BatchPersistenceError，携带未确认列更新与 reset/claim/final 阶段。确认部分在内存原 DataFrame 同步，最终计数与 active_keys 释放不重复执行。

例如认领 A、B 时提交 status/config_hash 两列，客户端只写入 A 后抛错：同范围读回确认 A 后，只重写 B 的这两列，不重写 A、不发送 AI 请求；若客户端已写入 A、B 但返回前抛错，两行读回均匹配即确认，无需再次更新。终态保存按相同规则处理六列，不因保存异常重新调用 AI。

KeyboardInterrupt 等 BaseException 不进入普通更新异常的核对重试分支；已经建立的 pending_patch 继续保留，交由运行模块按原收尾和异常传播规则处理。

本节仅用于 worker 的按需列更新。初始化 write_tasks 失败直接传播异常，由用户清空后重跑，不复用更新重试与读回确认流程。

按需列更新须保持未提供列不变；状态与五个结果列是否能共同一致写入、异常后能否及时读回，由用户接入真实 cli 验证，目前未验证。读到成功状态但正文缺失时报告不一致，不自动修复。
