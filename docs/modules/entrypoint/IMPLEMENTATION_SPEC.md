## 1. 目的与范围

让用户在安装运行依赖并填写配置后，通过 `python -X utf8 main.py` 启动已有任务表的批量处理。入口负责取得调用方配置、准备日志、创建唯一数据客户端，并直接调用 run_worker。月份切分由运行模块负责，任务读取、状态恢复和保存由任务模块负责；入口不构造读写回调。

本规格只描述已有任务表的 worker 启动，不自动初始化、创建或清空任务表。worker 入口不增加命令行配置参数，沿用既有运行逻辑和 YAML 字段结构；调用接口改为显式提供 cli、task_path、AI 配置路径及总日期范围。独立初始化的接口与流程由 [初始化启动规格](../initialization_entrypoint/IMPLEMENTATION_SPEC.md) 和任务规格维护，不属于本入口。

删除 `integration/use_cli.py` 及其 run_existing_tasks 转发入口。`integration` 保留既有一次性初始化模块和无启动副作用的包入口，本次不迁移初始化。任务配置放在根目录 `job_config.yaml`，AI 配置放在根目录 `ai_config.yaml`；配置字段及文件位置保持原约定，不新增替代 worker 接入文件或旧转发接口的兼容入口。

## 2. 输入与前提

目标环境为 Python 3.8，安装现有 `requirements.txt` 的依赖，以及用户提供的、支持 `from xdata.client import get_client` 的 `xdata` 包。后者的分发名称、版本和安装来源未知，不向依赖清单添加猜测的包名或版本；README 说明按已有数据环境的安装方式准备。

调用方配置固定为项目根目录下的 `job_config.yaml`，按 UTF-8 读取。它提供任务路径、AI 配置路径、可选的总日期范围和日志设置；`source_path` 等已有配置项保留，但本入口不读取源帖子。用户须将示例任务路径替换为实际已有任务表。

AI 配置文件及其同目录可选 `.env` 沿用配置模块的格式。数据客户端的连接配置和认证必须按现有 `xdata` 环境提前准备；入口不假设 AI 的 `.env` 同时承担数据连接配置，也不为未知的 `xdata` 配置增加字段。

调用方仍须保证只有一个 worker 操作同一任务表。根据用户确认的契约，`cli.read` 使用 YYYY-MM-DD 字符串表示按日左闭右闭范围，末日包含全天；真实日历时区、末日全天覆盖，以及 `cli.update_by_index` 的按原复合索引更新契约，继续由用户接入验证。入口原样传递总范围，不承担分月或边界转换。

## 3. 总体执行顺序

执行脚本时：导入依赖并定义入口函数 → 调用 `main()` → 根据脚本位置确定项目根目录 → 读取调用方 YAML 并校验入口所需字段 → 解析和检查 AI 配置文件路径 → 配置日志 → 在当前调用线程执行一次 `cli = get_client()` → 直接调用一次 `run_worker(cli, task_path, config_path, start_time, end_time)` → 由 worker 完成校验、读取、处理、保存和收尾 → 返回其统计并正常退出。

仅导入 `main` 模块时不调用 `main()`，不读取配置、不执行 `get_client()`，也不启动 worker。`from xdata.client import get_client` 和 `from ai_batch import run_worker` 放在文件顶部；依赖包自身的导入行为由各包负责。移除旧接入函数导入以及描述读写回调的失效注释。

## 4. 读取配置与确定路径

1. 项目根目录由 `Path(__file__).resolve().parent` 确定，不依赖终端当前目录，也不调用 `chdir` 或修改 `sys.path`。
2. 从该根目录的 `job_config.yaml` 读取 UTF-8 内容，使用 `yaml.safe_load`。解析结果必须为字典；空文件、列表或标量配置拒绝执行。
3. `task_path` 与 `ai_config_path` 必须存在且为非空白字符串。校验不裁剪或改变实际传入的任务路径；其他已有配置项保持原值。`logging` 存在时必须为字典，其选项是否有效由标准库 `logging.basicConfig` 校验。
4. `ai_config_path` 为绝对路径时沿用；为相对路径时相对于项目根目录解析。解析后的路径必须指向存在的文件，随后以绝对路径替换本次 `settings` 中的该项。入口不在此阶段解析 AI 配置内容或加载 `.env`，这些仍由 worker 内的配置模块处理。
5. `task_path` 是传给 `xdata` 的数据标识，不按本地文件路径解析，也不检查其是否在本机存在。总 `start_time/end_time` 保留原值交给既有 worker，不另实现日期解析或分月逻辑。

例如项目位于 `D:/batch_project`，配置为 `ai_config_path: "ai_config.yaml"`，最终交给 run_worker 的是 `D:/batch_project/ai_config.yaml`。即使从其他终端目录使用脚本的绝对路径启动，也读取同一份调用方配置和 AI 配置。`task_path: "ai_tasks"` 则仍原样交给 worker，并最终用于 cli 读写，不会变成 `D:/batch_project/ai_tasks`。

例如总范围为 `2021-01-01` 到 `2021-12-31`，入口仅传递这两个配置值；worker 按自然月处理左闭右闭范围，每个完整月份的截止日为月末。job_config.yaml 的全年示例同步采用这两个日期。两端相同表示处理该日全天；两端都未设置时沿用 worker 的单次无界读取；仅设置一端、反向范围或日期不合法时，由 worker 在业务数据读取和更新前拒绝启动。

配置文件缺失、编码或 YAML 解析失败、字段校验失败、AI 配置文件不存在时，不调用 `get_client()`，也不访问任务表。使用 PyYAML 现有 `safe_load` 语义，不增加一套不同于接入配置现状的重复键或未知字段校验；配置维护时应保证各键唯一。

## 5. 日志与客户端

入口在创建客户端前初始化标准日志。有 `logging` 配置时将其选项传给 `logging.basicConfig`；未提供时采用 INFO 级别，以及当前示例的时间、级别、模块、线程和消息格式。已有根日志处理器不被覆盖。`httpx` 与 `httpcore` 的日志级别设置为 WARNING，与 README 的既有运行建议一致；入口不创建日志文件。

日志配置失败时不创建客户端。日志准备完成后，在 `main()` 的当前线程执行一次 `cli = get_client()`。保留同一个 `cli` 直到本次 worker 返回或异常结束，不按月份、批次或帖子重复创建，也不把客户端创建放到模块导入阶段或网络线程中。

`get_client()` 的异常继续传播，不重试、不将读取失败解释为任务表为空。客户端的关闭协议未知，入口不猜测 `close()` 或上下文管理器接口；按现有 `xdata` 生命周期约定运行，这一项须在真实环境验证。

## 6. 启动批量处理

在客户端创建后直接调用 run_worker 一次，逐项提供同一个 cli、原 task_path、已解析的 AI 配置绝对路径，以及 settings 中可选的总 start_time/end_time，直接返回其 RunSummary。调用形式为：

~~~python
return run_worker(
    cli,
    settings["task_path"],
    settings["ai_config_path"],
    start_time=settings.get("start_time"),
    end_time=settings.get("end_time"),
)
~~~

入口不把整个 settings 字典传入核心、不绑定路径闭包、不构造 TaskCallbacks。run_worker 将 cli 和 task_path 交给每段 TaskStore，由任务模块直接访问数据。实际处理顺序、日期分段、更新列、状态转换和异常收尾沿用运行与任务规格。

入口不调用初始化函数，不读取 `source_path`，不额外读任务表，不重新调用 worker，也不在 worker 异常后继续下一月份。AI 配置内容和日期范围的合法性仍由 worker 在任务表读取或更新前校验；此时数据客户端已创建，但入口没有进行业务读写。

## 7. 输出与异常边界

`main()` 正常返回 worker 的原始统计对象；正常完成和各阶段进度由既有日志输出，不再打印一份可能与 worker 口径不同的统计。worker 正常结束但包含单帖失败时，继续沿用其成功/失败统计，不将单帖失败改成全局异常。

`main()` 自身不吞掉异常，供调用方保留原异常类型及 worker 附带的未确认保存信息。直接执行脚本的最外层捕获普通异常时，在该 except 中调用 `logging.getLogger(__name__).exception("批量处理未完成")`，由 Python 标准日志输出当前异常、具体消息、调用栈及异常链，然后以退出码 1 退出。不自行提取消息、设置空消息回退或遍历异常链，不添加错误分类。依赖导入失败仍由 Python 直接报告并非零退出，此时尚未调用入口。

例如 TaskValidationError 的“任务表必须恰好包含约定的九个普通列”和 ConnectionError 的“数据库连接超时”均由标准异常输出显示；包装异常的 cause/context 也由标准库处理。空异常消息只显示类型，保留原始信息。入口与 worker 各自已有的异常边界直接使用标准日志，不引入记录标记或去重判断。

入口不主动打印配置、认证信息、DataFrame、帖子或响应内容；异常消息和 traceback 中的源码行由标准库原样格式化。不新增重试、任务读写、结果导出或数据修复。main() 被其他应用调用时继续原样返回或抛出异常，不增加异常日志副作用。

直接执行脚本遇到 `KeyboardInterrupt` 时以退出码 130 退出。中断和 worker 异常仍先经过 worker 原有收尾，入口不绕过收尾、不补写状态，也不增加重试。正常返回退出码为 0，包括 worker 正常完成但有单帖最终失败的情况。

独立进程结束后，worker 异常对象中仅存在于内存的未保存结果仍会丢失；入口不新增错误文件、结果导出或保存失败后的数据修复能力。此限制沿用现有库，不将进程退出描述为全部结果已保存。
