## 2. 输入与前提

环境为 Python 3.8，已安装 `requirements.txt` 的依赖与用户提供的 `xdata` 包，并准备好其连接配置。只有独立运行依赖 `xdata`；导入原接入函数不导入它。安装来源、认证方式和客户端关闭协议未知，不猜测相应接口或配置。

项目根目录 `job_config.yaml` 提供 `source_path`、`task_path` 和可选 `logging`。目标为新的任务表路径；不得在已初始化的表上重复运行。入口不验证目标是否存在，注册与重复执行的效果由真实客户端决定，不能承诺重复注册安全或拒绝覆盖。初始化期间只有当前程序写入该目标。

客户端需支持用户提供的三个位置参数调用 `cli.register(task_path, "timeseries", "")`，以及既有 `cli.read` 与 `cli.write(task_path, df)`。类型固定为 timeseries，第三个参数原样使用空字符串，其业务含义尚未验证；不新增配置字段、命令行参数或根据异常切换其他注册方式。

cli 读取的源为全部现有帖子的 DataFrame，须保留层名及顺序为 ["date", "id"] 的原双层 MultiIndex，id 为唯一字符串，普通列具有字符串 `text` 和 `user_name`，不要求提供 id 普通列。不再兼容单层 date 索引加 id 列；接入层只沿用原索引，合法性继续由任务模块统一校验。真实源字段 user_name 是用户已确认的事实；核心输入和任务表统一使用 user_name，接入层不做字段重命名。按每帖一行、源读取顺序初始化，不排序、过滤、分组、去重或转换日期。AI 配置、密钥和 `start_time/end_time` 不参与这一步。

## 3. 总体执行顺序

模块执行 → 调用无参数 `main()` → 根据模块位置读取并校验任务 YAML → 配置日志 → 导入 `get_client` 并创建一次客户端 → 调用一次 `initialize_existing_posts(cli, settings)` → 接入函数完整读取源，原样提供源对象与写入回调 → `initialize_tasks(source_df, write_tasks)` 校验源、构造完整任务表 → 核心调用一次接入提供的 write_tasks 回调 → 回调注册目标 → 回调完整写入一次 → 返回原统计并退出。

仅导入模块时不启动、不读取配置、不导入 `xdata`、不创建客户端、不访问数据。不解析命令行，不读取启动操作参数。

## 4. 配置、日志与客户端

1. 根目录取 `Path(__file__).resolve().parent.parent`，以 UTF-8 和 `yaml.safe_load` 读取其 `job_config.yaml`。不调用 `chdir` 或修改 `sys.path`；常规 `python -m` 命令在项目根目录执行。
2. YAML 结果必须为字典；`source_path`、`task_path` 必须为非空白字符串，并且字符串不能完全相等。数据路径原样交给客户端，不解析成本地路径。不同标识是否指向同一物理表由调用方保证。
3. `logging` 存在时必须为字典，选项交给 `logging.basicConfig`；缺省使用 INFO 与时间、级别、模块、线程和消息格式。已有根处理器保持不变，不创建日志文件。独立运行只在 `main()` 配置一次日志，接入函数不重复调用 `basicConfig`；直接在已有应用调用接入函数时由应用配置日志。
4. 上述准备失败时不导入 `xdata` 或创建客户端。准备完成后，在 `main()` 内执行 `from xdata.client import get_client` 和一次 `cli = get_client()`；后续源读取、目标注册和完整写入复用同一个客户端，在当前线程串行执行。导入或创建失败直接传播，不重试，不调用未知关闭方法。

例如配置源为 `posts`、目标为 `ai_tasks`，调用依次为 `cli.read("posts")`、核心校验与构造、`cli.register("ai_tasks", "timeseries", "")`、`cli.write("ai_tasks", tasks)`。即使配置含 2021 年的 worker 起止日期，初始化仍读取全部源帖子，不要求 AI 配置文件存在。

## 5. 源数据接入与完整任务构造

`main()` 只调用一次 `initialize_existing_posts(cli, settings)`，直接返回其统计。启动函数不构造任何 DataFrame，不直接调用数据读写或重复实现初始化算法。

接入函数的输入为调用方客户端和含 `source_path/task_path` 的配置；调用方保证字段可用。执行顺序为：一次 `cli.read(settings["source_path"])` 取得全部源帖子 → 取得目标路径 → 定义绑定同一 cli 与 task_path 的 write_tasks 回调 → 调用一次 `initialize_tasks(source, write_tasks)` → 核心完成源校验与任务表构造后调用该回调 → 回调先注册目标，再完整写入 → 接入函数直接返回核心的 `InitializationSummary`。该函数不增加另一套入口配置校验，不重复配置日志，不读取任务目标，不构建任务表。

write_tasks 的输入是核心已经构造的完整任务 DataFrame。回调先且仅调用一次 `cli.register(task_path, "timeseries", "")`；正常返回后，再且仅调用一次 `cli.write(task_path, df)`，传递收到的同一个完整 DataFrame，不复制、排序、切分或重新构造。注册返回值不参与判断，不根据其真假改变流程；异常直接传播，不吞掉重复注册等错误，不自动重试。注册动作不得放在调用 initialize_tasks 之前，确保源校验与构造失败时不注册目标。

回调实现范围固定如下，不改变核心初始化签名：

~~~python
def write_tasks(df):
    cli.register(task_path, "timeseries", "")
    cli.write(task_path, df)

return initialize_tasks(source, write_tasks)
~~~

删除 `source.rename`，将 cli.read 返回的同一个源对象直接交给核心，不在接入层复制、重命名或另做字段校验；原 date/id 索引、顺序、字段值和类型不变。源缺少 user_name（即使只有旧 username）时由核心抛出 TaskValidationError("任务缺少必要列") 并禁止写入。源同时具有 user_name 和额外 username 时按核心的既有额外列规则，仅提取 user_name；真正重复的列名仍由核心列唯一性校验拒绝。

例如原帖 user_name="账户A"，核心读取 user_name="账户A"，写出的任务表也保存 user_name="账户A"。不填充缺失值或把其他类型强制转换成字符串，数据有效性继续由核心负责。任务表中的用户名列统一为 user_name，九列数量、其他字段及 worker 处理流程沿用原设计。

核心模块负责全部源校验和任务构造：保留原 date/id、text/user_name，设置 `status="0"`、空摘要和空结果字段，按源顺序构造完整表并调用写回调一次。源为空时仍写入结构合法的零行任务表并返回零数量；该表是实际输出，不是任何上层提供的占位输入。正常完成时，完整流程只读取源一次、实际目标读取零次、注册目标一次、完整写入一次；空源也先注册后写入合法的零行任务表。

具体源索引、字符串、唯一性校验与任务字段初始值按任务规格执行，不在启动和接入层复制。本次只扩展接入回调的目标准备职责，初始化公开函数的参数、函数名称与返回统计均保持原样，不增加另一套建表函数或兼容入口。

## 6. 输出、失败与退出

`main()` 返回原 `InitializationSummary`，正常完成数量由既有核心日志报告。客户端、源读取、校验、目标注册或完整写入失败直接传播，不返回部分成功，不自动重试、读回、续写或清空。

源读取、核心校验或任务表构造失败时，不调用 register 或 write。register 抛普通异常或中断时，不调用 write，原异常由核心继续传播；register 可能自身已经产生资源副作用，不以异常证明目标不存在。register 正常返回后 write 抛错时，注册可能已生效，目标也可能残留部分数据；初始化判失败，不再次 register 或 write，不使用 read 检查或自动删除资源。回调整体正常返回才报告成功，现有日志、普通异常具体原因、异常对象与退出码沿用既有行为，不新增阶段状态、错误分类或特殊捕获分支。

例如任务表构造完成后 register 抛出异常，本轮 register 调用一次、write 调用零次；若 register 正常返回而 write 抛出 DataNotFoundException，本轮 register 与 write 各调用一次，仍按原异常报告失败，不能假定补注册能解决所有路径或连接问题。真实目标状态由调用方核查；重跑须使用尚未注册的新 task_path，或按真实客户端规则处理原目标的注册状态与内容。本工具不猜测注销、删除或覆盖接口。

`if __name__ == "__main__"` 直接调用 `main()`。正常返回退出码为 0；最外层捕获所有普通异常，统一记录异常类名和具体原因，以退出码 1 结束，不按异常类别隐藏消息。具体原因取 `str(error).strip()`；消息为空时才使用“异常未提供具体原因，请检查依赖、配置和数据连接”的固定提示。不增加异常类型分支、分类或错误码。捕获 `KeyboardInterrupt`，记录固定中断提示并以 130 结束。现有顶部依赖导入失败由 Python 报告并非零退出。程序内调用 `main()` 保留原异常类型和对象。

例如抛出 `TaskValidationError("索引必须为名称和顺序固定的 date/id MultiIndex")` 时显示该校验原因；抛出 `ConnectionError("数据库连接超时")` 时显示“数据库连接超时”；缺少源 user_name 时显示 TaskValidationError 的“任务缺少必要列”消息。统一保留具体原因，不要求用户另行执行诊断脚本。

失败提示继续说明已开始写入时可能残留部分数据、须清空后重跑。入口只记录类型与异常消息，不主动打印配置、DataFrame 或 traceback；消息中由异常产生方提供的字段名、文件路径或连接说明会按原文显示，不承诺过滤外部消息中的全部值。完成初始化后启动 `main.py` 处理已有任务，不再次执行建表入口。
