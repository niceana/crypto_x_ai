# 加密资产信息事件驱动 Alpha 研究计划书

**版本：研究总览版｜2026-10-16 同步现行三轮实现**

**研究对象：50 个加密资产相关 X 账号历史帖子**  
**研究方向：AI 信息事件识别、事件研究、量化 Alpha 挖掘**

本文说明研究目标和后续研究方向。当前运行格式、检索与保存规则已同步三轮实现，详细约定见 [三轮方案](第一轮+第二轮+第三轮计划.md)、[事件运行规则](../rules/EVENT_RULES.md) 和 [表结构](../data/EVENT_RESULT_TABLE.md)。价格关联、Alpha 检验、分类和模型升级建议属于后续研究，不表示程序已经实现。

## 一、项目背景与研究动机

加密资产市场具有全天候交易、较高波动性、信息传播速度快、价格受市场关注度及项目事件影响明显等特点。

在一个高度全球化、全天候运行，但交易制度、流动性和信息质量并不均衡的市场中，资产价格由真实使用需求、投资者预期和边际资金流共同决定，而杠杆和代币供给机制又进一步放大了这种变化。

与传统证券市场相比，加密资产中的部分项目缺少稳定的现金流估值基础，市场对技术进展、商业合作、代币经济机制、网络安全事件及市场叙事的预期变化，可能成为影响价格的重要因素。

本研究目前拥有约 50 个加密资产相关 X 账号的历史帖子采集资源，覆盖 BTC、ETH、SOL、AAVE、UNI、LINK 等不同类型的加密资产。

从初步观察来看，这些账号的发文内容主要包括两类：

1. **日常传播与社区运营**：产品介绍、社区互动、活动宣传、生态资讯转发、既有信息重复传播等。
2. **项目动态与信息披露**：技术升级、产品发布、商业合作、治理决策、代币经济调整、安全事件等。

因此，相较于传统的社交媒体情绪分析，本研究更关注这些帖子中是否包含能够影响市场预期的**实质性信息事件**。

研究希望利用 AI 对非结构化帖子进行识别和整理，将其转化为可用于定量分析的事件数据，再结合历史市场行情，检验不同事件是否具有价格影响及可交易的超额收益预测能力。

上述数据特征目前属于初步观察，具体事件占比、信息质量及预测价值，仍需通过样本分析验证。

## 二、研究目标

### 2.1 总体目标

建立一套基于 AI 的加密资产信息事件研究方法，从历史 X 帖子中识别具有经济意义的事件，研究其对相关代币的价格影响，进一步挖掘具备可重复性和样本外预测能力的事件驱动 Alpha 因子。

研究最终希望回答三个核心问题：

**问题一：什么信息值得关注？**

不同账号发布的内容中，哪些属于具有实际经济含义的信息事件？哪些只是日常运营或重复宣传？

**问题二：什么事件会影响价格？**

不同类型、不同阶段、不同信息增量的事件，是否会引起显著的异常收益、交易量或波动率变化？影响方向和持续时间是否存在规律？

**问题三：什么事件具有 Alpha？**

当事件已经公开、投资者能够获得并执行交易时，是否仍存在能够预测后续超额收益的信号？这些规律在扣除风险暴露和交易成本后是否仍然成立？

### 2.2 阶段性目标

研究分为三个逐步递进的目标：

- **事件识别能力**：证明 AI 能够较准确地从历史帖子中提取、结构化和聚合实质性事件。
- **事件价格效应研究**：建立事件与历史行情的关联，识别具有统计意义的价格反应规律。
- **Alpha 因子研究**：提取事件特征，验证其对未来收益的预测能力，并评估可交易性。

三者需要依次验证，不预先假定事件数据一定能够产生 Alpha。

## 三、研究范围与基本原则

### 3.1 数据范围

第一阶段以现有 50 个加密资产相关 X 账号为主要研究对象。

研究数据包括：

| 数据类型 | 主要内容 | 作用 |
|---|---|---|
| X 原始帖子 | 正文、发布时间、账号、帖子 ID、引用及转发等信息 | 原始信息来源 |
| 账号元数据 | 账号性质、关联代币、采集覆盖范围 | 明确信息来源与目标资产关系 |
| 历史市场数据 | 价格、成交量、必要的流动性指标 | 研究事件价格反应 |
| 市场基准数据 | BTC、ETH 或加密市场整体收益等 | 控制共同市场因素 |
| 历史事件上下文 | 同一事件此前已观察到的披露与进展 | 识别重复信息及事件阶段 |

首轮以已有数据为主，不预先要求构建完整的外部新闻、治理论坛和链上数据库。

如研究发现官方帖子存在明显的信息披露滞后问题，再有针对性地补充相关来源。

### 3.2 核心研究原则

**原则一：事件优先，不强制进行资产分类。**

不预先将 50 个代币固定划分为公链、应用服务、社区叙事等类别。

这些分类有助于理解资产，但不是事件识别的必要前提。只有当后续研究发现资产属性能够解释事件收益差异时，才考虑将其作为辅助变量。优先保障事件召回率。 避免round1事件提取遗漏可能有价值的事件。

**原则二：客观识别事件，价格结果独立检验。**

AI 主要负责识别事件事实、阶段、信息变化和潜在经济作用路径，不直接根据主观判断给出买卖结论。

事件是否具有价格影响，由历史市场数据检验。

**原则三：重点关注信息增量。**

同一事件可能经历提出、批准、实施、结果披露等阶段。

研究不简单把相关帖子全部视为独立事件，也不将所有后续公告一概认定为重复信息。

**原则四：严格遵守历史信息边界。**

对任一历史时点，只允许使用该时点之前能够获得的信息。

不能利用后来发生的代币回购、项目转型、治理结果或币价走势，反向修改历史事件判断。

**原则五：区分价格影响和可交易 Alpha。**

事件公布后价格发生变化，不代表投资者能够捕获全部变化。

Alpha 研究必须考虑信息获得时间、处理延迟、交易执行、市场风险及交易成本。

**原则六：控制研究复杂度，先验证再扩展。**

优先实现可靠、可解释、可复核的事件抽取流程，不在第一阶段设计庞大的资产知识图谱、复杂评分体系或自动交易系统。

## 四、研究总体框架

研究采用：

**round1事件提取 → 事件导入与向量检索 → round2事件去重归组（按需调用 AI）→ round3事件影响分析（new/update）→ 事件数据库 → 后续价格研究与 Alpha 验证。**

### 4.1 round1事件提取：单帖事件事实提取

**核心任务：判断帖子中是否包含具体事件，如果有，客观概括发生了什么。**

round1事件提取采用轻量 AI 模型，对原始帖子逐条进行处理。

当前第一轮 AI 请求只输入任务表的 text 正文；帖子 ID、发布时间和用户名保留在任务表中供程序定位及导入。引用内容只有已经包含在 text 中时才会被模型看到，不单独读取或补充。

AI 输出顶层仅有 events 数组，每个事件对象仅有 event 和 tickers：

```json
{
  "events": [
    {"event": "ABC协议提出将20%的协议收入用于回购ABC代币", "tickers": ["ABC"]}
  ]
}
```

其中：

- `events`：事件对象数组，可以为空或包含多个事件；不输出 needs_review。
- `event`：客观事件事实，保留关键主体、动作、状态、数字及条件。
- `tickers`：目标代币字符串数组；为空时导入程序按原 user_name 查账号映射，无映射则在写入前停止本次全部导入。缺少 tickers 字段属于第一轮输出错误。

**round1事件提取不要求事件分类，也不要求复杂的主体、阶段、金额等独立结构化字段。**

这些信息只要存在于原文中，应尽可能保留在一句话事件描述里。

例如：

- “计划上线”不能概括为“已经上线”。
- “提出回购”不能概括为“执行回购”。
- 原文包含具体金额或比例时，应保留相应数值。
- 一条帖子包含多个独立事实时，应分别提取。

round1事件提取不负责：

- 判断事件是否首次出现
- 判断是否与历史事件重复
- 判断事件重要性
- 判断利好或利空
- 预测代币价格
- 对资产或事件进行复杂分类

普通问候、空泛宣传、纯观点和普通价格播报，可以输出空事件数组。

但所有原帖均保留，以便后续复核和研究其他信息因子。

### 4.2 中间程序：历史相似事件检索

**核心任务：为当前事件找到少量可能相关的历史事件，缩小round2事件去重归组 AI 的判断范围。**

round1事件提取输出候选事件后，由程序按照发布时间顺序处理。

程序只从当前发布时间之前已知的事件记录中检索候选，不允许使用未来信息。

当前采用已部署的 bge-m3 纯向量检索，只编码固定 event，不使用关键词、BM25 或排名融合。向量保存在事件去重分析表 embedding 列，不增加独立向量数据库或 SQLite 缓存。

候选限定为同币、披露时点前 180 天的已完成关联记录；按 event_id 归组，每组取最高余弦分数，只提交达到阈值的最多 10 个事件组，不补足候选。阈值默认 0.50，是待样本标定的试运行值。

无合格历史或所有组低于阈值时，程序自动 new；接口、向量解析或保存失败则停止，不伪造空候选。自动 new 不证明全网首次或确实没有历史关联，须通过样本评估漏关联率。update/repeat 仍须由第二轮 AI 判断。

### 4.3 round2事件去重归组：事件关联与信息增量判断

**核心任务：当前信息是否属于已有事件？如果属于，它有没有新增事实？**

round2事件去重归组 AI 接收：

- 当前 event、asset、发布时间、record_id 和 source_post_id，不读取或发送原帖正文
- 程序选出的最多 10 个达标事件组
- 各组截至当前披露以前的起点、update 时间线及披露次数

AI 只需判断以下四种关系：

| 判断 | 含义 |
|---|---|
| `new` | 当前信息未匹配到已有事件 |
| `update` | 属于已有事件，但提供了新进展或事实 |
| `repeat` | 重复已有事实，未提供明确新增信息 |
| `uncertain` | 无法可靠判断事件关系 |

约定输出：

```json
{
  "event_relation": "update",
  "matched_event_id": "E001",
  "new_information": "AAVE回购提案已通过治理投票"
}
```

`matched_event_id` 对 update/repeat 必须是本次候选 ID；new/uncertain 的匹配 ID 和 new_information 均须为 null。update 须有非空新增事实，repeat 的 new_information 须为 null。程序将合法 uncertain 按 new 独立建组，并在原始回答中保留 uncertain；新事件完整事实保留在 event 中。

round2事件去重归组同样不判断利好利空，也不预测未来收益。

**round2事件去重归组重点区分两种情况：**

- **同一事件的不同阶段**：例如回购计划从提出、批准到执行。
- **相似但独立的事件**：例如不同月份分别发生的回购、销毁或产品上线。

不能简单地因为事件都包含“回购”“升级”等关键词，就将其合并为同一件事。

### 4.4 round2事件去重归组的模型适配与成本优化

优先测试：

**一条当前事件 + 最多 10 个达标候选事件组，一次 AI 调用完成关联判断。**

这种方式能够减少调用次数，并利用上下文进行比较。

如果样本表明较弱模型在多候选比较中表现不佳，再评估逐对比较方案；当前没有实现自动切换：

**一条当前事件 + 一条历史事件 → 判断两者关系。**

逐对比较如何汇总须另行确定，不能假定已有对应调度和结果合并能力。

为控制成本：

- round1事件提取明确无事件的帖子，不进入round2事件去重归组。
- 无历史或所有组低于阈值时自动 new，至少一个组达标才请求第二轮 AI。
- 合法 uncertain 按 new 保存；无效输出按原请求预算重试，耗尽则失败，不自动切换更强模型或创建复核任务。
- 保留模型原始输出，便于错误分析和重新处理。

### 4.5 事件聚合与数据库组织

完成round2事件去重归组后，建立两个层次的数据记录。

**事件（Event）**：表示一项具体事件或持续性计划。

**披露（Disclosure）**：表示某个时间点关于该事件的一次信息发布。

例如：

| 日期 | Event ID | 披露内容 | 关系 |
|---|---|---|---|
| 3 月 1 日 | E001 | AAVE 提出回购计划 | new |
| 3 月 5 日 | E001 | 再次介绍原计划 | repeat |
| 3 月 10 日 | E001 | 治理投票通过 | update |
| 3 月 20 日 | E001 | 首次执行回购 | update |

同一个事件可以关联多条帖子。

具有新信息的披露需要保留独立记录，不能在聚合时直接删除。

对于重复宣传，也应保留原始帖子及其关联关系，后续可以作为注意力传播的研究数据。

这样最终得到的不是简单的去重帖子列表，而是可以还原事件发展过程的历史披露数据库。

### 4.6 第三轮经济影响与后续分类

第三轮独立处理 new/update，repeat 按规则跳过。输入包含原帖正文、当前 event、代币、关联和新增信息；update 另提供当前披露以前的本组历史，不再读取 Top 10 候选。第三轮评价本次有效新增事实的经济影响，输出 direction、materiality、certainty、persistence、materiality_reason；当前只做五字段非空字符串校验，正式提示词及评分取值还须定稿。

第三轮结果不预测收益或输出买卖指令。下述事件类型分类是可选的后续研究，与当前五字段经济影响分析分开。

事件分类不放在round1事件提取执行。

在完成事件识别和聚合后，再根据研究需求，对有效事件及披露记录进行分类。

分类可以围绕：

- 技术与产品
- 商业与生态
- 代币经济和供应
- 治理与规则
- 安全与风险
- 交易与资金
- 经营指标
- 社区与叙事

具体分类体系不在当前阶段固定。

优先通过初步事件样本了解真实数据分布，再决定是否需要细分事件类型。

该步骤可以使用规则、人工标注或轻量 AI 批量处理，**不作为必须执行的round3事件影响分析 AI 调用**。

此外，事件事实描述需要始终保留，以免简单类别标签丢失关键经济信息。

### 4.7 历史价格关联与 Alpha 研究

完成事件数据库后，再由程序匹配历史行情。

以具有新增信息的披露为主要观察对象，计算事件前后的收益、成交量和波动率变化。

建议初步使用：

- 事件前 24 小时
- 事件后 1 小时
- 事件后 24 小时
- 事件后 3 天
- 事件后 7 天

价格研究分为两部分：

**事件影响研究**

研究信息公开前后的市场反应，识别哪些事件具有显著的异常收益或波动变化。

**可交易 Alpha 研究**

从事件能够被系统识别并实际执行交易的时点开始计算收益，控制市场 Beta、动量、流动性及交易成本。

事件识别模型不得使用事件发生后的价格数据，以避免事后信息污染。

## 五、数据结构设计（V1.1 更新）

数据结构采用分层保存原则，不要求round1事件提取 AI 直接生成完整事件数据库。

### 5.1 原始帖子层

由采集与程序处理保存：

- 帖子 ID
- 账号及关联代币
- 发布时间
- 原始文本
- 引用、回复及转发关系
- 数据来源和采集状态

### 5.2 round1事件提取事件候选层

主要保存：

- 原始帖子 ID
- ai_response_content 内的 events/event/tickers JSON
- 提示词及请求参数摘要、状态、原始输出和调用信息

一条帖子可以对应多个候选事件。

### 5.3 事件关联层

由程序和round2事件去重归组 AI 共同生成：

- record_id：当前披露 ID
- event_id：本条建组 ID 或匹配到的历史组 ID
- `event_relation`
- `new_information`
- 当前披露时间
- 相关原始帖子

### 5.4 最终事件数据库

主要包含：

- `event_id`：事件标识
- `record_id`：披露记录标识，与原 date 组成索引
- 事件及新增事实描述
- 事件关联关系
- 原始证据及发布时间
- 可选的研究标签

原帖由现有采集流程保存。本项目建立第一轮帖子事件提取表和第二、三轮共用的事件去重分析表，不为事件组另建主表。事件表为 14 个普通列，含 embedding、两轮状态及摘要、round2_ai_response 和 round3_ai_response；第三轮五字段保留在回答正文 JSON 中，不拆成数据库五列。

需要能够追溯每一条最终事件记录对应的原始帖子和 AI 判断结果。

为保持历史回测有效性，事件状态应按历史时间记录，后续披露不能反向覆盖早期的信息状态。

## 六、研究实施路径（V1.1 更新）

### 第一阶段：事件识别与聚合可行性验证

**核心问题：轻量 AI 能否可靠提取事件，并通过后续匹配和判断形成有效事件库？**

主要工作：

1. 检查 50 个账号的原始数据和时间覆盖情况。
2. 分层抽取约 1,000—2,000 条历史帖子。
3. 测试round1事件提取极简事件提取提示词。
4. 人工检查重大事件漏检及事实提取错误。
5. 测试程序化历史相似事件检索。
6. 测试round2事件去重归组事件关系判断。
7. 比较多候选判断和逐对判断的效果。
8. 形成初步事件数据库。

主要验收指标：

| 模块 | 核心评价 |
|---|---|
| round1事件提取 AI | 事件召回率、误报率、事实描述准确性 |
| 候选检索 | 正确历史事件是否进入候选集合 |
| round2事件去重归组 AI | 新事件、进展、重复事件的判断准确性 |
| 完整流程 | 事件聚合质量、信息保留程度、模型成本 |

人工核查不仅覆盖 AI 提取的事件，也需要从 `events=[]` 的帖子中抽样，检查漏检情况。

本阶段不要求验证 Alpha。

**交付成果：**

- round1事件提取提示词与极简输出规范
- 程序化历史检索方案
- round2事件去重归组提示词与判断规范
- 测试样本和人工验收结果
- 初版事件数据库
- 完整流程的准确性与成本评估

### 第二阶段：历史事件库建设与价格影响研究

在第一阶段通过验收后，扩展至全部可用历史帖子。

主要工作：

1. 批量识别历史事件。
2. 根据发布时间顺序建立事件关联。
3. 形成完整事件与披露数据库。
4. 根据实际数据分布确定必要的事件分类。
5. 匹配历史价格、成交量和市场基准。
6. 计算异常收益、波动及事件前后变化。
7. 寻找具有潜在预测价值的事件特征。

**交付成果：**

- 完整历史事件数据库
- 事件频率与分布分析
- 不同事件的价格效应研究
- 候选 Alpha 研究方向

### 第三阶段：事件驱动 Alpha 验证

对第二阶段发现的潜在有效规律，进行更严格的收益预测和可交易性检验。

主要研究：

- 事件类型、阶段与信息增量
- 具体事件事实和经济参数
- 事件前价格与成交量变化
- 不同市场状态下的预测能力
- 不同收益预测期限
- 扣除交易成本后的可实现收益

采用时间顺序划分样本，进行样本外验证。

同时控制重复事件、市场共同风险、幸存者偏差、多重检验及模型过拟合等问题。

**交付成果：**

- 候选事件 Alpha 因子
- 样本内与样本外检验结果
- 交易成本与策略可行性分析
- 值得持续跟踪的事件信号

## 七、主要研究风险

| 风险 | 主要影响 | 应对方式 |
|---|---|---|
| round1事件提取漏掉事件 | 后续流程无法发现 | 高召回策略，随机核查无事件帖子 |
| 简短描述丢失事实 | 历史检索和事件研究失真 | 保留原文，要求保留关键动作、状态、数值 |
| 相似事件检索遗漏 | 同一事件被拆成多个事件 | 测试候选召回率，调整检索范围 |
| round2事件去重归组混淆事件进展 | 错误聚合或重复计数 | 对独立事件、周期性事件建立测试样本 |
| 历史信息泄露 | 夸大预测能力 | 严格按时间顺序处理 |
| 官方账号不是首次信息源 | 价格可能提前反应 | 明确区分采集数据中的首次观察与真实首次披露 |
| 账号与代币关联不直接 | 错误归因 | 保留账号角色和事件实际主体 |
| AI 成本过高 | 难以规模化 | 简化输出、程序检索、按需调用round2事件去重归组 |
| 事件没有可交易收益 | 研究效果无法转化为 Alpha | 区分事件价格效应与实际交易收益 |

## 八、阶段推进原则

项目采取逐步验证方式。

- 第一阶段证明事件识别与聚合是否可行。
- 第二阶段验证事件是否具有系统性价格影响。
- 第三阶段研究能否获得可重复的可交易 Alpha。

只有上一阶段具备足够的数据质量和研究价值，才扩大下一阶段投入。

不预先设定必须发现有效 Alpha 的目标。

## 九、预期研究成果

本研究希望形成三项可持续利用的成果：

**1. 结构化事件数据资产**

将历史 X 帖子转化为具有事件关联关系、披露时间和事实描述的数据库。

**2. 可复用的 AI 事件处理能力**

形成一套低成本、易扩展的“轻量抽取—历史检索—信息增量判断”处理流程。

**3. 事件驱动 Alpha 研究能力**

通过事件与价格数据研究，寻找具有经济解释力、可重复性和样本外预测价值的信号。

即使最终未发现稳定 Alpha，事件识别与历史信息整理本身也可以用于项目研究和动态监测。

## 项目核心方法论

**AI 负责从文本中发现和理解事实，程序负责建立历史关联，市场数据负责判断价格效应。**

整个研究不预设哪种事件一定有利于币价，也不要求模型根据主观判断筛选 Alpha。

最终目标是：

**将非结构化的加密资产官方信息转化为可复核的历史事件数据，再通过严格的统计与样本外检验，发现真正具有预测价值的事件驱动 Alpha。**
