# 向量写入事件去重分析表与阈值调整

更新日期：2026-10-16。用户已确认 JSON 对象格式，事件去重分析表尚未创建，直接在初始化结构中新增列；用户授权 AI 建议默认阈值，首版采用 0.50 作为待样本标定的试运行起点。本方案取代 [上一版方案](EMBEDDING_RETRIEVAL_PLAN.md) 中的 SQLite 保存及“有历史必发round2事件去重归组”规则。

## 1. 已确定的目标和保留规则

本次向量方案只新增一个普通列 `embedding`，当时普通列由 16 个变为 17 个。随后用户确认第三轮回答合列及两轮调用信息保存，当前共 14 个普通列，加两个索引共 16 项，以 [现行表结构](../data/EVENT_RESULT_TABLE.md) 为准。索引继续使用原 `(date, record_id)`。新事件导入时 embedding 初始化为空字符串，生成向量后按原索引仅更新该列；两轮已有状态、关联与分析结果保留。

继续只编码固定round1事件提取 `event`，调用已部署 bge-m3 的兼容接口，默认每批 8 条。用户确认模型已输出归一化向量，程序直接保存返回数值并用内积计算余弦相似度，不再归一化或转为 float32；历史仍要求同币、前 3 个日历月且严格早于当前时点、round2事件去重归组已完成。同刻记录不互相成为历史，保存关联后才推进。

本次取消 SQLite 读写、cache_path 配置及相关测试，不增加第二份本地持久缓存。实际已有 SQLite 文件不自动读取、迁移或删除；它不再是正式运行的输入。

## 2. 已确认选择

| 项目 | 方案或需要的信息 | 影响 |
| --- | --- | --- |
| 阈值数值 | 默认 similarity_threshold 为 0.50，允许配置 [-1, 1] 内的有限数值。 | 用户授权先建议试运行值，尚未以实际关联样本标定；调高会增加自动 new，调低会增加round2事件去重归组调用。相似度不是事件同一性的概率。 |
| 一列中的格式 | JSON 对象，字段为 model、model_version、config_hash、vector。 | config_hash 只包含服务地址、模型、版本和编码规则，不含 event；同一配置生成的各行摘要相同。标识不匹配时只重新生成所需行的向量，不重做已完成关联。 |
| 第二轮输入 | current 只含 published_at、event；candidates 每组只含 candidate_id 和 history 事件列表，每条历史含 published_at、event。每条 published_at 是对应 df 的 date 索引值的字符串，保留完整精度和时区。用 E1、E2 等短编号替代真实 event_id，不发送资产、披露标识、增量、次数或截断标记，也不读取或发送原帖正文。 | AI 返回 matched_candidate_id，程序校验后映射为真实 event_id，重试沿用本请求的输入及映射，数据库结构不变。第一轮 event 作为完整且固定的事实输入，时间筛选由程序负责；第三轮只读取本条 asset、event、new_information，不读取正文或组历史。 |
| 达标组数量 | 达标组按相似度排序，最多 10 组，不补足。 | 只有 2 组达标就发 2 组，超过 10 组时取前 10 组。 |
| 模型输出 | 模型已归一化；接口返回值经校验直接保存，用 float64 数组计算内积。 | 只校验单位范数，不修改分量；服务返回未归一化向量时按无效输出重试，耗尽后停止。 |
| 旧表新增列 | 事件去重分析表尚未创建，直接修改初始化结构。 | 本次不增加旧表自动加列或迁移功能；缺 embedding 列的旧结构仍报错。 |

模型权重或编码方式在服务端变化而模型名称不变时，使用者仍需更新 model_version。配置标识不含 event、密钥、批量、重试或 threshold；单独调整这些运行参数或筛选阈值可复用已有向量。event 沿用导入后的固定输入约定；人工修改 event 时必须清空对应 embedding 并另行确定关联及下游重算范围，配置摘要不检测正文变更。已经完成的round2事件去重归组关联保持原结果，阈值仅作用于后续待处理记录。

## 3. 处理顺序

1. 初始化直接包含空字符串 embedding，读取时检查现行 14 个普通列；不增加旧表迁移或其他普通列修复。
2. 按配置日期读取第二轮任务，有待处理记录时才读取必要的前 3 个月历史；沿用状态恢复、窗口内前史和补录冲突、当前 AI 配置及摘要检查。第二轮不读取第一轮表或原帖正文。没有待处理任务时不生成新向量。
3. 根据原索引选出本范围全部待处理披露，以及满足“同币，且至少一个待处理时点 t 存在 t-3个月 ≤ 历史发布时间 < t”的第二轮已完成历史。所有筛选都在已经读取的内存表中完成，不逐条查数据库。空字符串或有效对象的模型/配置标识不匹配时重新生成。匹配的对象须能解析为正确结构、向量有限非零且为单位向量、维度一致；新响应及表内复用均保留原数值，不做归一化或 float32 转换。编码规则标识更新为 event-only-service-unit-f64-v3，按新规则生成所需向量。格式损坏时停止提示，不作为没有历史或低分。
4. 内容相同的 event 在本次内存中去重生成；对应多行时仍分别写入各行的 embedding 列。有效旧向量优先复用，新生成的有效批次通过现有按列更新与存储重试保存；成功后才同步内存。存储失败不重复请求该批 Embedding。
5. 向量准备、保存结束后才认领关联任务。批量保存成功的向量可在重启后直接从事件去重分析表复用；只有向量不代表round2事件去重归组已完成。
6. 对合格历史逐条评分，按 event_id 取最高分；仅保留组分数大于等于 similarity_threshold 的组，按分数降序取最多 10 组，同分按 event_id 升序。
7. 无历史，或所有事件组都严格低于阈值时，直接保存 new，event_id 为当前 record_id，round2事件去重归组完成、round3事件影响分析待处理。日志分别记录无历史或阈值放行及阈值、最高分，便于核查。
8. 只要至少一个组达到阈值，就组织达标组的 3 个月窗口内历史，不回查窗口外起点。内部缺起点时仍设置 first_disclosure=null、history_trimmed=true，并保留 first_available_disclosure；发送第二轮 AI 前按候选顺序分配 candidate_id 短编号，只提供编号和 history 事件列表，每条历史含原 date 索引值和完整 event。起点或最早可用披露与全部 update 按原顺序提供，同一披露只发送一次。真实 event_id 映射固定在本次请求内供校验和保存，重试不重新检索或编号；具体输入见 [事件规则](../rules/EVENT_RULES.md#6-round2事件去重归组调度和输出)。向量接口、解析或存储错误仍停止，不作为低分或无历史。

使用默认值 0.50 时，A 组最高分 0.49、B 组 0.50、C 组 0.85，只提交 C、B；若所有组最高分都低于 0.50，直接 new。边界使用计算出的浮点分数直接比较，不增加隐藏宽容区间。0.50 仅为试运行起点，不是已经验证的最佳阈值。

例如仅处理 2021-01-02 的 ETH：2020-12-01 已完成披露在 3 个月窗口内，准备或复用其向量；2010-01-01 的组起点在窗口外，不读取它或生成其向量，近期披露仍可召回该组。内部保留截断标记，第二轮 AI 只收到候选短编号和可用事件文本。当前任务即使没有历史，也生成并保存自己的向量，供随后时点使用；提前生成向量不会让该行提前成为历史。

每批 Embedding 与每条关联 AI 分别计请求预算，默认最多 3 次且包含首次。两者复用 common.network 的六类可重试连接/读写异常、指数随机退避及 Retry-After 解析：网络传输故障、429、5xx 和无效接口输出共用该批预算；其他非成功 HTTP（如 401）直接停止。429 和 5xx 的合法 Retry-After 与本地退避取较长等待，429 不再首次出现即停止，预算耗尽仍停止本轮。表内 JSON 损坏、程序异常及存储失败不进入请求重试；存储仍使用独立预算。向量响应解析保留自己的格式校验，不复用聊天答复解析器。

以 1024 维响应为例，每条 embedding 必须是一维、非空且维度与本轮其他向量相同的数值数组；不接受布尔值、字符串、NaN、正负无穷或全零数组。只校验范数与 1 的绝对误差不超过 1e-5，不除以范数、不缩放分量。响应中的浮点数按原值保存为 JSON，内存用 float64 数组直接计算，重启复用时同样保留数值。两条模型已归一化向量的余弦相似度就是 1024 个对应分量乘积之和，批量计算为历史矩阵 (N, 1024) @ 当前向量 (1024,)。例如模型返回 [0.6,0.8] 和 [0.8,0.6]，直接算得 0.96。程序检查实际响应维度一致，不把 1024 写死成另一项配置。
